# PRの上書き相殺とその防止策

## 何が起きていたか

並行して走るPRが、古いスナップショットのファイル全体をそのまま
コミットすると、直前にマージされた別PRが同じファイルへ加えた変更が
「意図的な削除」として記録され、コンフリクト無しに main から消える。

実例（2026-11-15）: PR #879 が WorldBoxClient.tsx に経済パネルの配線を
追加した15分後、PR #881（ロビー）が古い版の同ファイルを丸ごと
コミットし、経済配線と presence の所有者キーが無言で消えた。
復旧は PR #882 が別途必要になった。ホームページ構成の巻き戻しも同型。

## 防止策（3層）

1. **ブランチ保護（main）**: PR必須・管理者にも適用・force push禁止・
   削除禁止に加え、必須チェック（`web-tests` / `overwrite-guard`）と
   「マージ前にブランチを main の最新へ更新」を要求する。
   これにより CI は古いスナップショットではなく実際のマージ結果を
   テストする。
2. **web-tests（CI）**: web の全テストを PR ごとに実行する。
   配線の消失は既存テスト（例: worldbox-economy の
   `client.includes("WorldBoxEconomyPanel")`）が検出する。
3. **overwrite-guard（CI）**: `tools/pr_overwrite_guard.py` が、
   PR が削除する行のうち「直近30日以内に他者が追加した行」
   「直近7日以内の大量削除」を検出して落とす。
   行の移動は数えない。ファイル丸ごとの削除は対象外
   （PRの一覧で見えるため）。

## 意図的な削除をするとき

機能の廃止などで上記の削除が正当な場合は、PRに
`confirm-removals` ラベルを付けるとガードは報告のみで通過する。
削除内容はCIログとサマリーに残るので、後から追える。

## 作業側の約束

- ファイル全体のアップロード（Web UIの upload / 全文 push）で
  既存ファイルを更新しない。必ず最新の main から引いた
  ツリーで差分コミットする。
- マージ前にブランチを main 最新へ更新し、CIの結果を見てから
  マージする。
