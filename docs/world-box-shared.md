# WORLD BOX 共有ノート（全 Muse 必読）

AGO WORLD BOX（web/app/games/worldbox）に関わる作業をする Muse は、**作業前にこのファイルを読むこと**。複数の Muse が並行して触るため、決定事項はここに集約する。新しい決定が出たら、実装と同じ PR か直後の PR でここを更新する。

最終更新: 2026-11-15

## 製品の前提

- AGO WORLD BOX は「ゲームの1つ」ではなく AGO のメタバース基盤。ワールドは単一の共有ワールドのみ。
- Discord との融合が核: プレイヤーの本人性・所属・経済は全部 Discord / AGO BOT 本体に紐づく。
- カタログ上は独立ジャンル「WORLD BOX」（web/lib/games-catalog.ts の GAME_GENRES 先頭）。

## 確定した決定（覆す場合はユーザー確認が必須）

### 世界と移動
- 見下ろし型。マップは 1024×1024、固定シード。北に雪原バイオーム。
- 同時接続プレゼンスあり（空間: world / lobby で分離）。他プレイヤーは向き反転＋補間移動で描く（瞬間移動させない）。
- プレゼンスの滑らかさは P2P 化せず、フレーム補完（スナップショット補間）で対応する（担当: deshihito 側）。SSE プッシュ化案は採用しない。
- スタミナ制: ダッシュ（モバイル=スティック強倒し、PC=移動キー2度押し）、水泳可（水中で切れたら最後の陸へ帰還）。ゲージはゼルダ式の円形をキャラ左上に。自動回復。
- ロビーは別空間（ファストトラベル往復、元の場所に戻る）。外形は図形の和集合。中央広場に掲示板・噴水・ワープ、左=ショップ街（あごむに店員）、右=カジノ、上=闘技場、下=鍛冶屋、北東=銀行、南西=休憩。ショップ翼2階=ギルドショップ区画。

### 国（ユニオン）
- 国 = Discord サーバーそのもの。建国できるのはサーバーオーナーのみ、国名 = サーバー名。市民 = そのサーバーのメンバー、役職は Discord 権限から導出（オーナー=国王、ADMINISTRATOR=大臣）。
- **国判定を持つのはユニオンマーク（建国の印）のみ**。首都の概念はマークに統合。マーク破壊 = レイド判定（将来の戦争レイヤーのトリガー）。
- 国は「所属区分」だけ。それ以外（建築・経済・作物）は全部ユーザー単位。ユニオン所有という概念は持たない。

### 建築・農業（プレハブ設置は禁止）
- 「家を設置」「畑を設置」は**やらない**。家はブロックを積む自由建築、畑は地面を耕して好きな作物を植える。
- ブロックは種類と耐久を持つ（ユニオン防衛の基礎）。入手はショップ購入＋マップ採掘の2ルート。
- 旧来の設置型 buildings（house/field/tower のプレハブ）は新モデルへの置き換え対象。繁栄度計算など旧仕様を前提に新規実装しない。

### 経済（案B ブリッジが唯一の正）
- 通貨は AGO コイン本体のみ。**Web 側で残高を直接増減しない**（ミント禁止）。
- Web は bot_kv 名前空間 `worldbox_economy` にオプを積み、Bot 側ワーカー（core/general/circulation/worldbox_economy.py）が pay_house / ウォレット / transfer_coins で適用する。earn はバンクロール（プール+国庫）の利益分のみ（Plan A）。
- profile 内の独自コイン（profile.coins）は廃止済み。読込互換のためだけに残っている。**復活させない**。
- オプ種別: spend / earn / transfer / steal / gamble。earn 理由はホワイトリスト制。
- カジノ（ロビー右翼）は実働施設: スロットマシンの前=スロット、カジノテーブルの前=ルーレットで実際に賭けられる。位置はサーバー側がプレゼンスで検証する。1プレイは gamble オプ1件（amount=ベット、payout=確定配当）で、ワーカーがベット引き落とし→配当（利益分は pay_house、負けは add_loss 還流）を原子的に適用する。抽選は Web サーバー側。ベット上限はブリッジの金額上限に一致（独自上限なし）。

### 行動の場所制約
- 購入はその店の場所でのみ（アイテムショップ等）。合成は作業台、精錬はかまど、というように行動は施設に紐づける。
- どこでもできるのは移動・採取などの基礎行動のみ。制限はサーバー側でも位置検証する。
- ショップ（売買）はロビー空間でのみ。経済パネルのショップタブとかばんの売却はワールドでは表示しない（PR #886）。サーバー側の位置検証は今後の課題。

### アイテム・インベントリ
- 基礎設計は「入口としての物量」優先。カタログ（web/lib/worldbox/items.ts）はデータ駆動で大量に持つ。追加はデータのみで。
- インベントリ 5 枠 = すぐ使う手持ち（ホットバー）、ストレージ 10 枠 = 持ち歩く裏の手持ち。
- 道具: ツルハシ（岩）、斧（木）、剣、クワ（耕す）。ティアあり。

### UI・文面
- **画面内に説明文・遊び方の文章を置かない**。全操作は画面内 UX（構造と導線）で完結させる。ラベルは断片のみ。絵文字は UI に使わない。
- Discord ログイン必須。ゲストモードなし。未ログインはゲート画面のみ。
- パネル（国・経済・マップ等）の開閉は画面左上の ≡ メニューに一本化。画面下のボタン行は廃止（PR #886）。
- 全体マップ表示モードあり（512×512、地形＋首都・建物・プレイヤーのマーカー、≡ メニューから開く。PR #883）。
- 描画はピクセル固定（座標の整数化、補間オフ）。マス目管理制が全空間の原則。

### 素材
- プレイヤーと店員は公式 `/img/nomal.png`（あごむに）。16px 化したあごむには却下済み、使うな。
- ユーザーが別チャットで作った確定素材セット（16×16、182点）: VM 上 `~/workspace/worldbox-pixel-art-td16/sprites/`。**`worldbox-pixel-art-REJECTED` は却下済みアーカイブ、使用禁止**。
- 地形タイルはリポジトリ `Assets/` のダンジョン素材を転用中（web/public/img/worldbox/）。

## 作業の進め方（衝突防止）

- 着手前に必ず最新の main を確認する。他の Muse が同じファイルを触っている前提で、**復元・巻き戻し系の変更をする前に現行 main の内容を読む**。
- WORLD BOX の主要ファイル（WorldBoxClient.tsx、economy.ts、profile.ts、items.ts）は特に衝突が起きやすい。大きな変更は PR を分け、タイトルに範囲を明記する。
- 本番デプロイは Pi の自動デプロイ（数分〜遅延あり）。「live に無い」=「消えた」ではない。まず main と live の到達点（どの PR まで出ているか）を切り分ける。
