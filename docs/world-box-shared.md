# WORLD BOX 共有ノート（全 Muse 必読）

AGO WORLD BOX（web/app/games/worldbox）に関わる作業をする Muse は、**作業前にこのファイルを読むこと**。複数の Muse が並行して触るため、決定事項はここに集約する。新しい決定が出たら、実装と同じ PR か直後の PR でここを更新する。

最終更新: 2026-11-17

## 製品の前提

- AGO WORLD BOX は「ゲームの1つ」ではなく AGO のメタバース基盤。ワールドは単一の共有ワールドのみ。
- Discord との融合が核: プレイヤーの本人性・所属・経済は全部 Discord / AGO BOT 本体に紐づく。
- カタログ上は独立ジャンル「WORLD BOX」（web/lib/games-catalog.ts の GAME_GENRES 先頭）。

## 確定した決定（覆す場合はユーザー確認が必須）

### リポジトリ上の扱い（2026-11-16、ユーザー決定）
- WORLD BOX は**別リポジトリへ分離する可能性が高い**。そのため Bot 本体のジャンル軸と並ぶ **1ジャンル**として扱い、境界を保つ（詳細は `docs/ARCHITECTURE.md` の「WORLD BOX は1ジャンルとして扱う」）。
- 境界の要点: 構成要素は `web/lib/worldbox/` + `web/app/games/worldbox` + `web/app/api/worldbox` + `web/realtime/` + Python 側 `core/support/worldbox/` と `core/general/circulation/worldbox_*.py`。外への依存は共通基盤（auth / bot-api 等）のみに寄せ、個別ゲームのロジックへの依存を増やさない。外から WORLD BOX 内部への import はしない（2026-11-16 実測で Web 側 0 件）。

### 世界と移動
- 見下ろし型。マップはチャンク式（座標＋固定シードの純関数生成）で実質無制限。北に雪原バイオーム。初回スポーンはランダムな陸地。所属国のマークへファストトラベル可。
- 同時接続プレゼンスあり（空間: world / lobby で分離）。他プレイヤーは向き反転＋補間移動で描く（瞬間移動させない）。
- プレゼンスの滑らかさは P2P 化せず、フレーム補完（スナップショット補間）で対応する（担当: deshihito 側）。SSE プッシュ化案は採用しない。
- テントは入れる室内空間（2026-11-15）: テント（facility）を置いて踏むと専用空間 "tent"（13×10、lib/worldbox/tent.ts、LobbyData と同形）へ入り、出入口パッドで戻る。内装には作業台とかまど（station smith）があり合成できる。空間はセーブ・プレゼンス・中継・ステーション検証すべてで world/lobby と並ぶ第3の空間として扱う。ステーション検証（station-online）はプレゼンスが無い/古い場合にセーブ（ワープ時の空間と入口位置）で代替する。
- プレゼンス中継は WebSocket 化した（2026-11-15、ユーザー決定）: 本番の起動エントリは web/realtime-server.js（standalone の server.js を内包するラッパーで、通常 HTTP は内部ポートの Next へ素通し、/api/worldbox/realtime だけ中継）。中継の純粋ロジックは web/realtime/relay-core.js、接続認証は短期署名トークン（POST /api/worldbox/realtime-token、セッションと同じ鍵）。REST プレゼンス（bot_kv）はフォールバックとして併存し、中継が落ちてもポーリングで遊び続けられる。位置は申告制だが、移動連続性の検証は中継・REST の両方に入る（下記の B4）。
- 注意（2026-11-15 実害発生→対処済み）: WS 接続中はクライアントが REST ハートビートを止める作りだったため、bot_kv プレゼンスが凍結し、bot_kv プレゼンスを位置の正にするサーバー検証（カジノ・ステーションゲート・ギルドボード・モブ攻撃の距離）が全部古い位置/不在で判定して死んだ（カジノで実害確認）。対処: クライアントは WS の有無と独立に REST ハートビートを併送し bot_kv の鮮度を保つ（heartbeatTick の lastRestHeartbeatAt、間隔は移動中500ms/静止2s）。モブ攻撃には申告位置フォールバックも併設（mobs ルート）。**bot_kv プレゼンスがサーバー検証の正であり、その鮮度を止めてはいけない**（Phase 2 で書き手が relay 集約へ移った後も同じ。下記の Phase 2 参照）。
- 同一アカウントは1タブだけ有効（2026-11-16、ユーザー指摘「タブを複製すると分身できる」への対処）: タブごとに識別子（tab）と開始時刻（tabAt）を持ち、サーバーは最新のタブのプレゼンスだけを受理する（判定は lib/worldbox/presence.ts の tabVerdict、保存は presence-online の putPresenceTabGuarded）。旧タブの REST ハートビートは 409（tab_superseded）で拒否され、WS 中継（relay-core の admitTab）でも世代交代時に旧接続を 4001 で切断し、旧世代の新規接続は受け付けない。無効化されたタブはプレゼンス送信とオンラインセーブを止め、「別のタブで開いています（このタブは無効）」とだけ表示する。タブ申告の無い経路（nations / warp のサーバー側書き込み、旧クライアント）は世代管理の対象外として従来どおり受理する。
- WS/REST の乖離の是正（2026-11-16 夜通し S3）: 中継（relay-core.js）がインスタンス空間（cave:/ruins:/dungeon:）を "world" へ潰し、役職・ランク・パーティを落としていたため、洞窟等のプレイヤーがワールドに幽霊表示され、WS 経由ではネームプレートが free/ランク1・ダンジョンの他パーティが見えていた。対処: 中継も presence.ts と同じ空間・境界（ワールド ±1,000,000、洞窟64・遺跡48・ダンジョン52）・役職規則で整形し、クライアントは WS 送信にも役職・ランクを載せ、WS 受信にもダンジョンのパーティ分離を適用する。2ミス猶予の境界も是正: REST はワールド48タイル外を間引くため WS だけで届く遠くの他者をポーリングの欠落に数えて消しては戻すチラつきがあった — WS 経由で 2.5 秒以内に見た者は欠落に数えない（wsSeenAt）。
- ポーリングの WS push 化（2026-11-16、ユーザー承認「Phase 0〜2を一括で設計・実装」）: コマンド系 POST（掘る/置く/売買/攻撃/カジノプレイ等）は冪等 ID・ロックがルート前提のため REST 維持が正。ポーリング系の読み取りだけを WS push 化する。**Phase 0（presence 間引き）**: WS 中継が健全な間（接続中＋20秒以内に応答。relay は15秒ごとに `{t:"tick", now}` を送り時計補正と生存通知を兼ねる）は presence の REST 取得を 1秒→15秒セーフティに落とす（判定は `web/lib/worldbox/realtime-poll.ts` の純粋ロジック）。セーフティ取得は「中継に繋がっていない相手」の回収用で、欠落カウントは取得ごとの回数のまま（セーフティ中、REST のみの相手の掃除は最大2×15秒まで遅れる。その間も WS の bye/prune が退室を担う）。切断・無応答なら 1 秒に即復帰する。入口近接判定はローカル計算のみのため 1 秒 tick で分離して常時回す。
- **Phase 1（relay のサーバー側一括 watch + diff 配信）**: relay プロセスが bot_kv を名前空間ごとに1回だけポーリング（速い系2秒: chat / union_board / party / tiles / mobs、遅い系5秒: board / nations）し、差分を WS で配る。bot_kv への経路は Next と同じ BOT 自前 API（/v1/query、同じ環境変数）で、relay 専用の最小クライアント `web/realtime/botkv.js` + 純粋ロジック `web/realtime/watch-core.js`（diff・購読スコープ解決）。配信の形は対象で分ける: **tiles / mobs / board は値そのものを差分配信**（クライアントは既存の parseTileOverride / parseMobState / parseBoardPosts で適用し、世代ガードも同じ規則で進める）。**chat / party / nations は poke（変更通知）**: 応答が本人向け加工（近距離フィルタ・partyView・Discord ギルド情報・国家設定の解決）を含むため relay では再現せず、対象クライアント（chat=同空間のみ、party=本体と索引から引いた関係者のプレゼンス ID のみ、nations=全員）へ通知だけ送り、クライアントは従来の REST 取得を1回だけ走らせる。クライアントは WS 健全な間これら6系統の定期取得を止め、初期表示は従来どおり REST スナップショット、**WS 再接続時は全系統を REST で再同期**する（push の取りこぼし対策）。bot-api 未設定なら watch は無効で従来ポーリングのまま動く。プロフィール（refreshInv）は Phase 1 の対象外で従来どおり 15 秒取得。**経済オプの確定 push（2026-11-16 追加、ユーザー指示「経済の反映が遅い件も」）**: watch 対象に `worldbox_economy`（2秒）を追加し、オプの pending→done/failed 遷移だけを「残高が動いた本人」（オプの userKey + 適用先 discordId + 送金先 toDiscordId + steal の fromDiscordId をプレゼンス ID に変換した相手）にだけ合図する。**push に金額・オプ内容は載せない**（全体 broadcast 厳禁。他人のオプを他人へ流さない）。クライアントは合図で refreshInv（残高）を即時実行し、`lib/worldbox/economy-push.ts` の DOM イベントで経済/カジノ/アリーナパネルも即時 refresh する。従来のポーリング（15秒束・カジノ/アリーナ3秒）は fallback として残す。ワーカー側の適用速度そのもの（POLL_SECONDS 適応化・Web ルートの server-side wait）は別 PR の担当で、ここでは「適用後の受け取り待ち（最大15秒）」を push で消す。**インスタンス状態も watch 対象に追加（2026-11-17）**: `worldbox_instances` を速い系2秒の poke とし、宛先はキーから解決する（共有状態=同じ空間、ダンジョンセッション=同じ入口の全フロア、遺跡の個人状態=本人だけ。週次クリア記録 `dungeonclear:` は対象外。解決は watch-core の instanceKeyScope が正）。これにより洞窟の共有枯渇とダンジョンのボス進行（階段開放）が他メンバーへ届くようになった。あわせてクライアントは、ダンジョンでモブを倒した本人もセッション状態を取り直し、パーティ取得はダンジョン内で `?space=` の要約経路を使う（従来はどちらも無く、倒した本人の画面でも階段が開かなかった）。
- **Phase 2（heartbeat 書き込みの relay 集約）**: relay が WS で受けた位置を bot_kv（worldbox_presence）へ直接書く。書き込み形式は presence-online.ts の putPresence と完全互換（キー=所有者キー、値=JSON.stringify({…heartbeat, ts})、ts はサーバー時刻）。所有者キーは中継トークンの payload に追加した `ok` で運ぶ（署名付きトークン内のみ。broadcast は従来どおり pid だけ）。スロットル（relay-core の planPresenceWrite が正）: 初回・空間遷移・4タイル超のジャンプは即時、移動中は最大1秒に1回、静止時は2秒に1回 — 検証側の鮮度は従来の REST 併送（移動500ms/静止2s）から大きく劣化させない。切断時は最終位置を鮮度つきで書き残し、bot_kv 側は鮮度切れで自然に消える（退室 DELETE は従来どおりクライアントの REST が担う）。**クライアントは relay の合図（接続時の `{t:"hello", agg:1}`）を受けた場合のみ REST ハートビートを止める**。合図が無い（bot-api 未設定・旧トークン）・WS 切断・relay の書き込み失敗継続（3回で `{t:"agg", on:false}` を broadcast し、復旧したら on:true で再開）の場合は即座に REST 併送へ復帰する — 「WS 接続中は REST を止める」だけだった過去の実害の形には決して戻さない。REST 経路と集約経路は同一キー・同一整形のため二重に書いても競合しない。トレードオフ: presence PUT が担っていた計測（recordPresenceMetric の DAU/ピーク）は集約中は記録されなくなる（REST fallback 中のプレイヤーは従来どおり記録される）。
- 移動連続性検証（2026-11-17 夜通し B4）: 位置は申告制のままでは station ゲート全体がスクリプトで突破できるため、サーバー側で前回位置からの移動量・経過時間で連続性を検証し、不連続なジャンプを却下する（クランプではなく却下。クランプは追従で数秒遅らせるだけ）。規則は presence.ts の checkMovementContinuity / checkSaveFallbackContinuity が正で、relay-core.js に JS ミラーを置く。閾値: 最大速度 10 タイル/秒（ダッシュ 7.0 + 約40%の余裕）、余裕 3 タイル（ノックバック最大2〜3と埋没救済の小幅なずれを吸収）、保管が 30 秒より古ければ新規入室として受け入れる。許容距離 = 10 × 経過秒 + 3。空間が変われば受け入れる（入退室・階段・テント・階層移動はすべて空間文字列が変わる正当な不連続）。正当な不連続のうちサーバー側の移動（ワープ/蘇生・復活）は、移動する側がプレゼンスとセーブの両方を目的地へ更新する（warp ルートの前例、vitals の settleDeath と sync 配送）。sync 配送の更新に失敗したら pendingTeleport/lastDeath を残して次回 sync で再送する。却下は 409 position_jump（保管位置つき）で返し、クライアントは保管位置へ直接戻る（findFreeNear を通さない。再却下の連鎖を避けるため）。WS 経路も同じ規則で、却下は `{t:"jump"}` で送り主へだけ返す。却下されたハートビートは保存せず、保管位置は最後の正規位置のまま（保管 ts は更新しない）。REST と WS の両方に同じ規則を入れる（片方だけ塞ぐと他方が抜け道になる）。中継は接続時に bot_kv のプレゼンス（無ければセーブ）を1回だけ読み、部屋に前回が無い再接続後の初回を照合する外部基準にする。読み終わるまで受信ハートビートをためておき、未照合のまま通さない。セーブ PUT も同じ規則で守る（基準は新鮮なプレゼンス。プレゼンスが古い/無いときはサーバー保存のセーブを固定 12 タイルで基準にする。初回作成・復帰時の findFreeNear のずれは 12 タイル以内に収まる）。
- 移動連続性の残る抜け穴（B4 で閉じていない）: 10 秒以上の無音（プレゼンスもセーブも止める）でテレポートし直すと、セーブ基準もプレゼンス基準もリセットされ受け入れられる。1回のテレポートあたり約 10 秒の無音コストがかかるため、瞬時の駅ホッピングは防げるが、辛抱強いスクリプトは防げない。なお DELETE でプレゼンスを消してからセーブを移すと、セーブ PUT がプレゼンス不在で受け入れられ、直後のハートビートも移転後のセーブを基準に通ってしまう（上記と同じ抜け穴の即座版）。セーブ PUT の固定 12 タイル基準は単発の遠方移転を防ぐが、連続 PUT で少しずつ寄せる這い寄りは防げない。これらを完全に閉じるにはサーバー側のテレポート許可証（ワープ/蘇生以外の移動を許可する記録）が必要で、今回は範囲外。
- 移動連続性の例外: 登録済み同一空間ワープ対（2026-11-17、階段バグ是正）: B4 の「空間が変われば受け入れる」は同一空間内のクライアント駆動ワープを漏らしており、ロビー擬似2F階段（LOBBY_STAIRS_UP (17,29)/(18,29) → 着地 (17.5,60.5)、DOWN (17,62)/(18,62) → 着地 (17.5,27.5)、約31〜35タイル）が全経路（REST 時刻基準/セーブ基準・WS 中継）で却下され「踏むと一瞬真っ黒になって同じ場所へ戻る」状態だった。是正は閾値緩和ではなく**登録済みワープ対の検証**: 保管位置からワープ元タイルへ到達可能な範囲内にあり、申告位置がそのワープの登録済み着地点の近傍（WARP_LANDING_TOLERANCE_TILES = 2.5）にある場合だけ正当な不連続として受け入れる。ワープ表は presence.ts の SAME_SPACE_WARPS が正（値は lobby.ts の階段定数が正で複製、relay-core.js にもミラー。worldbox-warp-continuity テストが三者の一致を固定する）。元タイルへの到達範囲は、時刻基準では通常移動の許容距離（10×経過秒+3）そのもの、セーブ基準では WARP_FALLBACK_SOURCE_REACH_TILES = 5（セーブに時刻が無いため、広場など元タイルから離れたセーブからは跳べない。往復の着地点⇔反対側の元タイルは 2 タイルなので 5 で覆える）。新しい同一空間ワープを足すときは、両方の表へ登録すること（片方だけだと他方が詰まる/抜け道になる）。ロビーのワープパッド (28,34) は world への空間変更なので対象外。
- 遺跡の転移罠はサーバー移動化（2026-11-17、同 PR）: 転移罠の転移先はサーバーが抽選で決めるためワープ対に登録できない。従来は転移先を応答で返すだけでプレゼンス/セーブを動かしておらず、クライアントの申告が同一空間内の跳躍として却下され転移が巻き戻っていた。instances ルートがワープ/蘇生と同じ型で、応答前にプレゼンスとセーブの両方を転移先へそろえるよう是正した。**サーバーが決める移動は、決めた側がプレゼンスとセーブを目的地へ更新する**（クライアント申告に任せない）。
- 移動連続性の既知の未対応（2026-11-17 監査で確認）: 水中で力尽きた際の「最後の陸へ帰還」はクライアント権威（スタミナがクライアント状態）の同一空間テレポートで、帰還距離が伸びると（泳ぎは最大約43タイル）連続性検証に却下されうる。実害は「帰還が効かず、救済スタミナで泳ぎ直す」形で硬直はしない。着地点が動的でワープ対に登録できず、サーバー側で陸・水を検証する帰還エンドポイント等の設計判断が要るため未対応として記録する（階段バグの PR には混ぜていない）。

### 国（ユニオン）
- 国 = Discord サーバーそのもの。建国できるのはサーバーオーナーのみ、国名 = サーバー名。市民 = そのサーバーのメンバー、役職は Discord 権限から導出（オーナー=国王、ADMINISTRATOR=大臣）。
- **国判定を持つのはユニオンマーク（建国の印）のみ**。首都の概念はマークに統合。マーク破壊 = レイド判定（将来の戦争レイヤーのトリガー）。
- 国は「所属区分」だけ。それ以外（建築・経済・作物）は全部ユーザー単位。ユニオン所有という概念は持たない。
- 国家設定（2026-11-16 バッチN1）: 国ごとの設定は bot_kv `worldbox_nation_settings`（キー = ギルド ID、lib/worldbox/nation-settings.ts + nation-settings-online.ts、入口 /api/worldbox/nation-settings）。**税率**（0〜10%、既定 5%）はギルドショップの売り手取り分から差し引く割合で、未設定国は 5%。税分は従来どおり積まない（シンク）で、累計だけ taxCollected に表示用として加算する。**公開/非公開**（visibility、既定 open）: private の国は繁栄ランキングと国一覧（参加先候補）に載らず、join は `nation_private` で拒否する（自国民には自国分だけ見える）。**大臣**は「王 > 任命大臣 ∪ Discord ADMINISTRATOR 大臣 > 国民」で解決する（nation-settings.ts の resolveMemberRole が正）: 王はギルドボード「設定」タブで国民を大臣に任命/解除でき、任命は現在の国民にだけ効く（国民でなくなれば自動で落ちる）。Discord 由来の大臣はゲーム内から解除できない（UI で区別表示）。設定変更は王のみ＋ギルドボード前（station "guild"）検証。役職の権限判定（ギルドショップ登録/撤去・戦争宣言・Discord 連携設定）はすべてこの解決を通す。

### 建築・農業（プレハブ設置は禁止）
- 「家を設置」「畑を設置」は**やらない**。家はブロックを積む自由建築、畑は地面を耕して好きな作物を植える。
- ブロックは種類と耐久を持つ（ユニオン防衛の基礎）。入手はショップ購入＋マップ採掘の2ルート。
- 設置ブロックは HP 制（2026-11-16、ユーザー決定）: 最大 HP = アイテムの durability（未定義の家具等は既定値10、tiles.ts の blockMaxHp）。採掘は1回=1ヒットで、ダメージは道具ティアで変わる（BLOCK_MINE_DAMAGE: 素手6/木10/石16/鉄25/ミスリル40。道具を要求するブロックはその道具のティア、道具不要のブロックは斧/ツルハシの高い方のティア）。ティアは**実効ティア = アイテムのティア + その道具の強化レベル**（2026-11-17、tiles.ts の bestToolTier が enhance を読む。洞窟鉱脈の段位ゲートも同じ実効ティアで判定する）。HP が残ればブロックは残ってアイテムは得られず、クライアントは残り割合でひび割れを描く。戦争中の他者ブロック破壊も同じ HP 経路を通る（1ヒット即消しにはしない）。hp の無い旧データは満タン扱い。コンテナ/装置の状態削除はブロックが壊れたときだけ（ヒットでは消さない）。
- 地形の岩・木も HP 制（2026-11-17、ユーザー指示「ミスリルで岩殴ったら1発で壊れた、耐久値が欲しい」）: 岩 TERRAIN_ROCK_HP=60 / 木 TERRAIN_TREE_HP=30（tiles.ts）。ダメージは設置ブロックと同じ BLOCK_MINE_DAMAGE（岩=ツルハシ、木=斧、素手の伐採は最低段6）。ミスリルでも岩は2ヒット。残り HP はタイル上書きの hp に保存し、クライアントはひび割れで描く（TileView.hpFrac）。壊れるまで収穫は出ない。再生（岩3時間/木6時間）・収量は従来どおり。
- 道具の耐久が実効化（2026-11-17、ユーザー指示）: カタログの durability（木60/石130/鉄250/ミスリル500）が道具の使用回数上限として効く。使用するたびに「その種類の最良の1本」（実効ティア最大、profile.ts の bestToolItem）が1摩耗し、尽きたら1本壊れて消える（profile.toolHp に使用中の1本の残量だけを持つ。スタック管理と両立させるための形）。対象行為: 伐採・採掘・耕作・ブロック採掘・地表/洞窟の鉱脈と倒木・モブへの剣攻撃。壊れたら応答の broke で通知し、クライアントはメッセージ+破片 SE を出す。スロットには残量バー（満タンでは出さない）。PvP（vitals 経由のキュー解決）は今回未配線。
- 道具の棲み分け（2026-11-17、ユーザー指摘「剣がピッケル枠になるのは良くない」）: ブロック採掘に使えるのは斧とツルハシだけ。actionForTile は剣・クワ選択中は mine_block を出さない（門は剣タップで開閉に戻る）。サーバー側のダメージ計算も元々 斧/ツルハシしか見ていないので、判定をクライアント側の入口で揃えた。
- 基本素材の直接設置（2026-11-15）: 木材・石材は素材のままでは置けないのが「設置できない」の実態だった（選んでもハイライトが出ず「そこではできない」だけ出る）。ItemDef.placesBlock で素材→ブロックの対応を持ち、木材はオークの原木・石材は石ブロックとしてそのまま置ける。消費は素材側、描画・耐久・掘り返し回収はブロック側の定義に従う。
- 旧来の設置型 buildings（house/field/tower のプレハブ）は廃止し、コードを完全撤去した（2026-11-16、ユーザー決定）: lib/worldbox/buildings.ts・buildings-online.ts・/api/worldbox/buildings は削除済み。**復活させない。** 繁栄度は国民数 × 5 のみ（建物の算入は廃止）。≡ メニューの「建築」パネルも中身が建物だけだったため導線ごと撤去した。bot_kv（worldbox_nations 名前空間の "buildings" キー）の既存データは残置するが、コードからは参照しない（到達不能）。

### 経済（案B ブリッジが唯一の正）
- 通貨は AGO コイン本体のみ。**原資の無い残高増額はしない**（ミント禁止）。増額は必ず pay_house でバンクロールから確保できた分だけ。
- Web は bot_kv 名前空間 `worldbox_economy` にオプを積み、Bot 側ワーカー（core/general/circulation/worldbox_economy.py）が pay_house / ウォレット / transfer_coins で適用する**のが従来経路**。earn はバンクロール（プール+国庫）の利益分のみ（Plan A）。
- **コイン適用の直接化（2026-11-17、ユーザー指示。PR #1048 / #1051 / 第2段b）**: 適用の正は bot-api 直接経路（`submitEconomyOp`、`web/lib/worldbox/economy-bridge-online.ts`）へ移行した。spend=残高 CAS（wallet と同じ規則）、transfer=`transfer_coins` RPC、earn/gamble=原資 RPC（次項）。直接経路が使えない環境（SQL 未適用・bot-api 未設定）では従来のキュー＋ワーカーへフォールバックし、冪等規則（適用台帳・claim・決定的 ID）は両経路で共通。金を動かした後の失敗でキューへ積み直すことはしない。
- **原資の正は Postgres（2026-11-17）**: `economy_pool_state`（単一行）＋ RPC（`economy_pool_pay_house` / `refund_house` / `add_loss` / `pay` / `refund` / `seed`、`docs/sql/economy_pool.sql`）。Python の `EconomyPoolStore` も同じ DB を正とし、JSON（`data/economy_pool.json`）は移行元とフォールバック専用（二重の正は作らない）。SQL 適用手順は PR #1051 本文参照。
- profile 内の独自コイン（profile.coins）は廃止済み。読込互換のためだけに残っている。**復活させない**。
- オプ種別: spend / earn / transfer / steal / gamble。earn 理由はホワイトリスト制。
- カジノ（ロビー右翼）は実働施設: スロットマシンの前=スロット、カジノテーブルの前=ルーレットで実際に賭けられる。位置はサーバー側がプレゼンスで検証する。1プレイは gamble オプ1件（amount=ベット、payout=確定配当）で、ワーカーがベット引き落とし→配当（利益分は pay_house、負けは add_loss 還流）を原子的に適用する。抽選は Web サーバー側。ベット上限はブリッジの金額上限に一致（独自上限なし）。
- カジノのゲームは Bot 側ギャンブルと Web /games の資産を移行して増やす（2026-11-15 追加分）: テーブル=ダイス（原典 play_dice、当たればベット×範囲）/ ブラックジャック（web/lib/blackjack.ts の純粋ロジック、3:2・ダブルあり）/ ダブルアップ（原典の倍率×1.6・内部モード遷移）、スロットマシン=セブンスロット（原典 slot7 の状態遷移・確変・天井・6ペナルティを移行）。セッション型は「開始時に spend で先払い → 終了時に prepaid の gamble 1件で精算」が決済の型。精算オプは先払いが done になってから作り、先払い失敗のセッションは無効化する。**先払いの直接提出（2026-11-17 是正）**: 先払い spend は `submitEconomyOp` で直接提出し、確定失敗ならセッション自体を作らない。直接適用が使えず pending になった場合だけ従来のゲート（プレイ前に done を待つ）が効く。ブラックジャックの hit/stand にも同じ確認ゲートがある（以前は精算時のみで、未確定のまま手を進められた）。セッションは1人1つまで、30分で期限切れ（未使用分は返金）。内部状態（確変・six カウンタ・内部モード）は bot_kv worldbox_casino にユーザー単位で永続化し、slot7 とダブルアップで共有する（原典と同じ）。適応: slot7 の 66666 全額没収はブリッジに手段がないため採用しない（そのスピンは報酬0）。slot7 の回数指定（10/50/100 を選んでまとめて先払い）は 2026-11-17 ユーザー指示で廃止: 開始は常に1回分の先払いで、回すたびに精算する。
- 精算の冪等性と処理速度（2026-11-16、二重精算と滞留の実害を受けて）: パネルは GET を3秒間隔でポーリングし、各リクエストが精算を走らせるため、カジノルートは同一ユーザーのリクエストをプロセス内ロックで直列化し、精算オプは決定的 ID（`settle-<先払いオプID>`、BJ 返金は `refund-…`、slot7 ペナルティは `penalty-…`）で積んで既存があれば作り直さない。**精算オプにランダム ID を使ってはいけない**（二重払いの温床）。Bot 側ワーカーは適応ポーリング（処理がある間は0.4秒間隔・バッチ上限まで処理したら即次バッチ、idle は最大1秒まで backoff）・最大100件/回で回し、claim の失効は90秒。ワーカーの読み取りは pending だけに絞る（KVStore.load_matching、jsonb contains）: 名前空間には終端オプが貯まり続けるため全件読みは件数に比例して遅くなる。全件読みは10分ごとの回だけ行い、壊れたレコードの終端化と終端オプの間引き（新しい順に1,000件だけ残す。履歴表示は直近20件/人しか読まない）をまとめて行う。ワーカーとその計測ストアは KVStore の remote_only（ローカル写し bot_kv.json と未送信ジャーナルを持たない）: set のたびの合本ファイル全体の書き直しが適用の律速だったためで、遠隔が落ちれば wallet も同じ API 経由で進まないので写しの意味がない。日次計測はオプごとに書かずメモリに貯めて20件/10秒で一括書き出しする。固定5秒時代は先払い→精算でワーカー周期が2周分積み重なり反映が最大十数秒遅れたため、Web ルート側も server-side wait（economy-bridge-online の waitForOpDone、200ms間隔・上限3秒、GET の精算駆動は1秒）を併用し、done 依存の処理（カジノ精算・アリーナ/PvP参加費・売買・送金）は同一リクエストで最終状態まで進める（予算超過時は従来のポーリングにフォールバック）。wallet 取得の例外はワーカー内で吸収する（外に出すと tasks.loop ごと止まって経済処理が無言で死ぬ）。
- 適用台帳（2026-11-17、構造問題#2「財布適用→結果書戻しの二重適用窓」の是正）: 適用そのものの冪等化は bot_kv `worldbox_economy_applied`（キー=オプID、remote_only、計測ストアと同型）が担う。ワーカーは claim 確認のあと、適用前に `applying` を書き、適用が終わったら `applied`＋適用額を書いてから結果を書き戻す。結果の書き戻しが失敗して同じオプが再処理されても、台帳が `applied` なら財布は触らず結果だけ書き直す（日次計測は `metricRecorded` フラグで二重加算しない）。台帳が `applying` のまま（適用の成否が曖昧）なら再適用せず `failed=apply_uncertain`＋critical ログで安全側に倒す。残高不足等の確定失敗は台帳も `failed` で終端化し、再処理で apply_uncertain に化けないようにする。台帳の書き込み自体に失敗した場合は適用に進まず、claim 失効（90秒）後の再試行に回す。台帳のエントリは終端オプの間引きのタイミングで一緒に消す（終端オプの台帳は二度と読まれない）。
- 即時 spend の交付ゲート（2026-11-17、構造問題#4「即時 spend の無担保交付」の是正）: profile の売買・強化、テント拡張、転職、依頼の納品・取消は、オプを積んだあと server-side wait（3秒）で終端を待ち、failed なら交付した状態を巻き戻して 409 economy_failed を返す（売買・強化はプロフィールを購入前へ、転職は変更前の役職へ、納品は両者のプロフィールと依頼一覧へ、取消は依頼一覧へ）。pending のままなら従来どおり交付し、クライアントのポーリングに引き継ぐ。テント拡張の決定的 ID は失敗オプが残ると再試行できないため、failed の既存オプは消してから積み直す（金は動いていない終端オプだけが対象）。依頼の投稿そのものは #1029 の escrow ゲート済みで、報酬・返金は escrow が done のときだけ動く。**残る窓**: wait（3秒）を超えて pending のまま後で failed になる場合は巻き戻しが届かず、交付だけ残る（ワーカー停止時など）。将来の是正は、失敗オプの定期的な突き合わせによる巻き戻しか、交付前の done ゲート（決定的 ID＋クライアントの再試行キー）への移行。
- 冪等性の総点検と横展開（2026-11-16 夜通し S1）: カジノ以外の経済経路にも同型の問題（ロック無しの read-modify-write ＋ ランダム ID）が残っていたため横展開した。共有基盤は `web/lib/worldbox/user-lock.ts` の `withUserLock`（キー単位のプロセス内ロック）と `economy-bridge-online.ts` の `enqueueEconomyOpOnce`（決定的 ID の冪等登録、既存があれば作り直さない）。適用先: 闘技場（ユーザー単位ロック＋賞金は `prize-<参加費オプID>`）、プロフィール売買・合成等（ユーザー単位ロック。二重売却＝コイン生成を防止）、ギルド依頼（依頼全体を固定キーで直列化＋ `escrow-/reward-/refund-<依頼ID>`。納品×取消の競合で報酬と返金が両方払われるのを防止）、広場の噴水・休憩（ユーザー単位ロック。残高検証のすり抜けとクールダウン競合を防止）、インスタンス（空間単位ロック＋遺跡の初回開封 earn は `ruinsCompleteOpId` = `ruins-done-<入口x>-<入口y>-<Discord ID>`）。**新しい経済経路を足すときは、状態の RMW とオプ登録を必ずロックで直列化し、「1回だけ払う」オプは決定的 ID ＋ enqueueEconomyOpOnce で積むこと。** 送金（economy ルート）は1リクエスト＝1回の意図的な送金でサーバー側の繰り返し契機が無いため対象外（記録済み）。

- カジノは1台1ゲーム（タブ式は廃止）: 北列=スロット台×3＋セブン台×3、中央=ルーレット/ダイス/ブラックジャックの専用テーブル、南列=ダブルアップ台×3＋スロット台×1。各機器は専用スプライト（slot7_machine / roulette_table / dice_table / blackjack_table / double_machine）で、機器判定 casinoMachineNear がゲームを返す。パネルは立っている機器のゲームだけを表示し、API も開始・操作とも機器一致を要求する。ピアノは station を外した（カジノ判定だけ出て遊べない罠だった）。

### 演出（アニメーション/モーション/パーティクル）
- 演出の計算は `web/lib/worldbox/fx.ts`（純粋ロジック）に集約する。行為の成功→ `fxEventsRef` 経由で描画ループが粒・揺れ・出現ポップに変換する配線が正。
- パーティクル: 同時上限 FX_CAP=260、1バースト最大26粒、寿命は短く（0.16〜0.9秒）。色は明暗を混ぜて背景を選ばない。形は chip/spark/drop/ring/puff/leaf/snow/glow。
- 行為の払い戻し: 伐採=木片、採掘=石片、耕す=土塊、植える=若葉、収穫=実りのきらめき、設置=土煙+出現ポップ、建築/破壊=破片+揺れ、入出水=水滴、ダッシュ=風の筋、ワープ=立ち上る光。タップへの即時応答として道具スイング+風切りを出す（結果の粒は成功時）。
- 環境粒: 雪原=雪、森=落葉、夜=蛍、それ以外=花粉。移動の副産物として足元に土ぼこり/水しぶき。
- 揺れはワールドのみ（ロビーはピクセル固定のため揺らさない）。`prefers-reduced-motion` では粒を絞り揺れを切る。
- モブ演出の語彙（第2弾）: 出現=`spawn`（煙と光が立ち上る）、被ダメージ=`hit`（赤/白/暗色の火花、寿命0.18〜0.38秒）、死亡=`death`（大きめの破片+煙、描画ループ側で小さな揺れ併用）。生成は `spawnMobFx` に集約し、モブの占有サイズ（1〜20マス）で粒数（最大2.6倍）・粒サイズ（最大2.2倍）・散らばりをスケールする。FX_BURST_MAX と FX_CAP の上限は常に守る。出現は出現ポップも併用可。
- 空振り（行為の失敗）は粒を出さず、風切りだけを薄く（WHIFF_ALPHA_SCALE=0.45）・細く・道具アイコンなしで出す。成功の粒は成功時にだけ出す原則は維持。
- 天候は決定的サイクル（fx.ts の `weatherAt`、WEATHER_PERIOD_SEC=360秒区間のハッシュで雨/晴れを決定、雨の比率は約35%）。サーバーを介さず全クライアントで一致させる。環境粒の優先順位は 雪 > 雨 > 森 > 夜 > 花粉（雪バイオームでは雨でも雪）。雨は spark の筋で速く落ちる。
- 時間帯の名前は fx.ts の `phaseKind`（dawn 0.18〜0.30 / day 0.30〜0.68 / dusk 0.68〜0.86 / night それ以外、daynight.ts の nightAmount と整合）。時間帯が切り替わったフレームでは新しい種類の環境粒を数粒追加で出す。
- ヒットストップ（2026-11-17、感覚面 B5）: 自分の攻撃の命中 45ms・撃破 80ms・被弾 35ms の間だけ、描画ループのシミュレーション dt（移動・モブ・粒・他プレイヤー補間）を 0 にして世界を止める（fx.ts の `startHitstop` / `hitstopActiveAt` が正、上限 120ms、長い指定が優先し短い指定では縮まない、`prefers-reduced-motion` では止めない）。壁時計ベースの遷移・タイマーとモブ行動状態機械（now ベース）のタイマーは止めない（停止は最大でも 80ms でタイマーのずれは知覚できない）。
- 素材別パーティクル（2026-11-17、感覚面 B5）: 破片の色は対象の素材で変える（fx.ts の `burstPaletteFor` が正。鉱脈・設置ブロック・地表/洞窟オブジェクトの ID から部分一致で引く）。洞窟・遺跡・ダンジョンの行為（採掘/宝箱/扉）も対象の位置で素材バーストを返し、温泉は水しぶきにする（従来は全部プレイヤー位置の poof で同じだった）。
- 他者の撃破でも死亡バーストを出す（2026-11-17、感覚面 B5）: 見えていた個体が状態だけで死んだ（他者の撃破が kv 同期で届いた）場合は消えっぱなしにせず死亡の粒を出す。自分の攻撃の結果とは `deathFxAt`（アンカー単位・1.5 秒）で二重に出さず、24 タイルより遠くでは出さない。
- 天候の遷移（2026-11-17、感覚面 B5）: `weatherAt` の区間境界では `WEATHER_BLEND_SEC=30` 秒かけて雨の強さを線形に混ぜる（fx.ts の `weatherBlendAt` が正、雨粒の数は強さに比例）。昼夜の暗さは `nightAmount` の連続関数で従来どおり滑らか（追加対応なし）。
- パネルの出現（2026-11-17、感覚面 B5）: 全パネル共通で 180ms の出現アニメーション（globals.css の `wb-panel-in`。位置指定のインライン transform と干渉しないよう translate/scale の個別プロパティで動かす）。閉じる側は即時（出現で統一）。カジノパネルはインラインの独自 `rootAnim` が優先される。
- 空間遷移はハードカットしない（2026-11-16、感覚面 B1）: ワープ/テレポート/リスポーンは 140ms フェードアウト→頂点で切替→220ms フェードイン（合計 360ms、遷移中は入力を止める）、初回入場は暗転から 220ms で明けるだけ、再接続は薄いパルス（不透明度 0.25・300ms）だけ。暗幕色はシェル背景（#0b0e14）と同一。遷移ロジックは `web/lib/worldbox/transition.ts`（純粋ロジック）に集約する。入場前にロビー/農場/モブ/洞窟のファイル素材を先読みし、初フレームの平色チラつきを消す（上限 2.5秒、超えたら未読込みのまま進む）。
- アフォーダンス（2026-11-16、感覚面 B2）: 近くの「使えるもの」（施設・出入口・宝箱/扉）は金色の脈動する輪で示す（`web/lib/worldbox/affordance.ts` が正。範囲はフットプリント端からチェビシェフ距離 2 タイル、脈動は鉱脈と同じ 0.35±0.25・周期約 1.5 秒）。鉱脈は採掘者の既存の脈動があるので輪の対象外、開封済みの宝箱/扉にも輪は出さない。施設種別ごとにセッション内初回だけ誘導バウンス（強めの脈動＋上下 4px の揺れ、900ms で収束）。無効操作は文言だけに頼らない: タップしたタイルに赤い輪＋小刻みな揺れ（260ms）＋ error SE（既存の低い矩形波 2 連）＋ピルの揺れ。ボタンは押した瞬間だけ 0.96 倍に縮む（`.wb-shell button:active`、シェル内限定）。施設チップは出現時に 240ms でポップする。スティックは掴んだらノブが 22→26px に大きくなる。`prefers-reduced-motion` では輪は静止・揺れは切る。

### 音響（BGM/SE、2026-11-15）
- 音響の基盤は `web/lib/worldbox/sound.ts`（譜面・対応表は純粋ロジック、再生は Web Audio 合成のみ）。カジノパネル内の効果音は従来どおり `lib/sfx`（カジノ演出の階級連動が正）。
- **opus っぽい音は禁止**（ユーザー指示）: 音声ファイル（.opus/.mp3 等）を使わない。BALKU 式のサイン波パッド wash＋ローパスで曇らせる作りも WORLD BOX では使わない。BGM は短く減衰する打鍵音（マリンバ風プラック）＋細い矩形波＋ノイズハットで組む決定的ループ、BGM バスにローパスは掛けない。
- BGM は場面で切り替わる（`bgmSceneFor`: カジノ > 洞窟/遺跡/ダンジョン > 屋内（ロビー/テント） > 夜 > 昼）。譜面は32ステップ固定で乱数生成しない。夜はリード疎ら・ハット/キックなしで一番静かにする。遺跡は E マイナー・84BPM・キックなしの専用曲。
- BGM の場面遷移は 1.2 秒のクロスフェード（2026-11-16、感覚面 B3）: 旧声のバスを絞りつつ新声を 0 から立ち上げ、2声を重ねる。SE と BGM はマスターバスで統一する（音量の比は従来どおり SE 0.9 / BGM 0.5）。タイマーが遅れた分は過去ステップを束で鳴らさず飛ばし、位相を保ってループの継ぎ目の段差を消す。全曲の hat/kick は 32 ステップ配列に統一する。
- 戦闘・危険時の緊張レイヤー（B3）: 敵対モブが 6 タイル以内か HP 25% 以下で、曲は変えず 1 小節に 2 打の低い心拍（短い減衰のサイン波サンプ、パッド wash・ローパスではない）を重ねる。判定はクライアントが 500ms ごとに行い、1 秒ごとの場面判定で ON/OFF する。ロビー・テントでは切る。
- SE は fx のバーストと同じイベントから出す（`seForFxBurst`、死亡=kill・出現=poof）。素材音（木/石/土/水）を作り分け、階層ゲインは sfx.ts と同じ配分（撃破 > ヒット > 行為 > 移動 > 足音）。足音などには連打防止の最小間隔がある。
- SE の手応え統一（2026-11-16、感覚面 B4）: 足音はバイオーム/空間で素材を変える（`footstepMaterialFor`、草・石・木・雪・砂・水。テント内は木、ロビー/洞窟/遺跡/ダンジョンは石、泳ぎは水）。同じ SE でも毎回まったく同じ音にしないため、再生ごとにピッチ ±6%・音量 ±8% のゆらぎを掛ける（`seVariation`、再生時のみでゲーム状態には使わない）。BGM はゆらぎの影響を受けない（dest を明示して呼ぶ声だけ）。同時発音は 80ms の窓に 6 発までで、それを超えた tier 4 以下（振り・足音・UI 等）は落とす（tier 1/2 は常に通す）。命中/撃破/コイン/成功にも連打防止の最小間隔がある（60/150/90/150ms）。モブ演出と行為イベントの SE はプレイヤーからのチェビシェフ距離で減衰させる（12 タイルで下限 0.15）。UI の操作音は ≡ メニューの開閉（open/close）とメニュー項目（click）に配線する。被弾の hurt SE はレシピだけあり配線なし（接触ダメージは hit バーストと hit SE が兼ねているため、別に鳴らすと二重になる）。
- UI の操作音の範囲拡大（2026-11-17、感覚面 B5）: シェルの `onClickCapture` でシェル内の全ボタン押下に click SE を鳴らす一本化にした（従来は ≡ メニューのみ）。固有の SE を持つ領域（≡ メニュー・経済パネル・カジノ・アーケード筐体）は `data-wb-se="self"` で除外し二重に鳴らさない。アーケード筐体の「閉じる」だけは筐体側で click を鳴らす。鳴らすか否かは従来どおり設定（SE トグル）が正。
- AudioContext は最初の操作（pointerdown/keydown）で解錠する。設定は localStorage `worldbox-sound`（BGM/SE 個別）、切替は ≡ メニュー内の「設定」の中（2026-11-17、ユーザー指示: BGM・効果音・通報は設定へ格納し、メニュー本体はアクションだけに保つ。ボタンは押したときの動作を示す）。非表示タブでは BGM を止める。

- 特殊オブジェクトは web/lib/worldbox/objects.ts（採取/鉱脈/宝箱/入口/温泉/魚影など22種、決定的配置＋ルート＋再出現）。モブは web/lib/worldbox/mobs.ts（48種、バイオーム・時間帯・ドロップ表。ダンジョン専用含む）。
- モブのサイズは 1〜20 マスで規定する（size×size 占有、アンカー中心）。サイズ帯: 1=小型 / 2〜3=中型 / 4〜6=大型 / 7〜12=巨大 / 13〜20=超巨大。大型（size>=4）はチャンク密度で出さずスーパーセル配置（セル一辺 size×2 チャンク、同種は最大1体）で疎らに置く。
- フィールド戦闘（2026-11-15 実働化）: モブは地表に実体として出る。個体は「種@アンカー」で識別し、HP と死亡（再出現15分＋個体キー決定的な追加遅延0〜10分、combat.ts の mobRespawnDelayMs）だけを bot_kv `worldbox_mobs` に持つ。攻撃はモブのタップ（タイル行為より優先、クールダウン350ms）。剣を選択中は照準方式でなく範囲方式（ユーザー指摘で変更）: タップで常に振り、攻撃範囲内のモブに当たる（対象は attackTarget が「タップを含む個体→近い個体」で選ぶ。範囲内にいなければ空振り）。攻撃範囲（MOB_ATTACK_RANGE）は 2（2026-11-16 に 1→2 へ拡大、ユーザー指摘「狭すぎる」）。距離検証の実位置ルール（2026-11-16）: モブの見た目はアンカーから最大 LEASH_DISTANCE=11 ほど離れて追跡してくるため、アンカー基準の検証では足元のモブにも too_far になり「ダメージが通らない」実害が出た。攻撃・技ともクライアントがモブの現在タイルを申告し、サーバーはリーシュ（MOB_REPORT_LEASH=13）内でのみ申告を実位置として採用する（combat.ts の resolveMobPosition）。状態・ドロップのキーは従来どおりアンカー。素手・他道具はモブの直接タップで攻撃する。サーバーが配置を再計算して実在を検証し、距離は占有範囲まで2マス以内。ダメージは闘技場と同じ式（素手8 + 所持する最良の剣 tier×4、arena.ts の playerAttack を共用）。ドロップは撃破時にサーバー抽選でプロフィールへ直接入る。動き（うろつき・敵対の接近・被弾後の逃走）と描画（素材スプライト・被弾フラッシュ・ノックバック・HP バー・出現ポップ）はクライアントの見た目だけの責務で、位置の真値は持たない。プレイヤー HP は実働（下記「プレイヤー状態」参照。モブは接触でダメージを与える）。 占有当たり判定と接触（2026-11-15 追加）: プレイヤーはモブの占有タイル（現在位置の footprint）へ入れない。当たり判定はクライアント側で、設置ブロックと同じ BlockedTiles 合成にモブ占有を重ねる（combat.ts の mobBlockedTiles / mobFootprintTiles）。占有の真上に立っている間はそのモブの占有だけ通す（閉じ込め防止）。接触は占有範囲までチェビシェフ距離1以内で検出し、敵対モブは接触開始時（継続中は1秒間隔）だけ軽いノックバック（combat.ts の knockbackTarget）＋ hit バーストを発火する。ダメージは /api/worldbox/vitals がサーバー検証して適用する（下記「プレイヤー状態」参照）。接触ダメージの距離検証も攻撃と同じ実位置ルールを使う（2026-11-17 是正）: クライアントはモブの現在タイルを mx/my で申告し、サーバーはリーシュ内でのみ採用する。アンカー基準のままだったため、追跡してきたモブの接触が too_far で無効化されていた（攻撃側の #989 と同型の未適用側）。中立モブは provoked（被弾して敵対化している間）だけ接触ダメージを与える: クライアントの送信条件とサーバーの受け付け条件（passive 以外）は一致させる。
- モブの HP バーの表示条件（2026-11-16、ユーザー決定）: バーは「自分が攻撃しようとした敵」にだけ出す（剣の範囲対象になった個体と、直接タップした個体。届かず外した場合も出す）。攻撃していない敵には出さない。従来の「傷ついた個体だけ出す」条件は廃止。倒した個体はリセットし、復活後は再び攻撃するまで出さない。記録はクライアント側の見た目だけの状態（revealedMobs）で、サーバー状態には影響しない。
- タイル上書きの読み込みと埋没救済（2026-11-16、読み込み遅延と「読み込み後に壁に埋まる」実害を受けて）: タイルの全件読み（loadTileOverrides）は全件 kvList を毎回走らせず、短TTLキャッシュ（3秒、書き込みはキャッシュへ即時反映）つきにする。クライアントは取得中心から48タイル以上離れたら先読みで取り直し、ワープ/スポーン（placePlayer）と初期位置の確定時にも即時取得する（マウント直後の取得は初期位置 (0.5, 0.5) 中心で実位置とずれるため、それだけに頼らない）。読み込み完了で固体が増えてプレイヤーが固体へ深く重なった場合は、描画ループの埋没救済（半径半分で重なり判定→ findFreeNear で脱出）が毎フレーム働く。浅い重なり（壁への密着）では発火させない。タイル書き込みの同期（2026-11-16 夜通し S4）: スキャン中に書き込みが入ると古いスナップショットでキャッシュを上書きする競合があるため、書き込み通し番号（epoch）で検出して書き込み分を重ねる。タイル行為の POST はタイル単位＋ユーザー単位の二重ロックで直列化する（ロック無しの二重タップで同一ブロックを2回掘れる）。クライアント側ポーリングの競合（2026-11-16 夜通し S6）: setInterval で回る取得は in-flight の重複と古いレスポンスの上書きを `web/lib/poll-guard.ts` の `createPollGuard` で防ぐ（begin → isCurrent → end。進行中はスキップし、明示的な再取得は force で古い取得を無効化）。適用先: カジノ 3s・チャット 3s・パーティ 4s・プレゼンス 1s・掲示板 10s・国家/プロフィール/モブ/タイル 15s・バイタル 15s・薬師の死亡地点 3s・インスタンス状態・ビルドバナー 15s。タイルとモブはさらに世代ガード: 取得開始後にローカル行為（掘る・置く・攻撃）で状態が進んでいたら古い応答は適用せず取り直す（倒したモブの生き返り・掘ったブロックの復活を防ぐ）。**新しいポーリングを足すときは必ずこのガードを通し、表示への反映は isCurrent 確認の後にすること。**

## インスタンス基盤＋洞窟（2026-11-16 バッチ2）
- 空間 ID は文字列 `"cave:<入口タイルx>,<入口y>:<層>"`（ruins/dungeon も同形式で予約）。セーブ（v6 のまま space を文字列として拡張）・プレゼンス・保存先 bot_kv のキーにそのまま乗る。入口の識別子は地表の入口タイル座標。
- 洞窟は共有マップ（個人インスタンスではない）。入口は maplogic の構造物配置（cave_entrance、スーパーセル方式）が正で、踏破で遷移（ダイアログなし）。帰還は各層のポータル→入口前に戻る。入口・階段の周囲1.5タイルは安全圏（モブを置かない）。
- 生成は決定的（シード＋入口座標＋層）: 64×64、ランダムウォーク＋部屋、3層・階段接続。鉱脈は層別プール（浅: 石炭/銅、深: 希少/水晶、最深: ミスリル鉱脈=新規定義 minTier 3）。段位ゲートはツルハシの実効ティア（ティア＋強化レベル。希少2+、ミスリル3+）。枯渇は共有（bot_kv `worldbox_instances`、キー=空間ID）で再出現は通常3h・希少6h、宝箱は6h（地表 cave_chest の respawnMs 0 は地表専用の意味として残す）。
- 明かり: 洞窟内は半径の外を暗くする。半径は所持で決まる（ランプ 9 / 松明 6 / 無し 2.5 タイル）。
- 温泉は1層目にあり、踏むと休憩（HP全回復＋毒消去）。休憩地点は入口の外（ワールド座標）として記録する。
- 洞窟モブは cave_bat / golem（配置は生成が正、個体状態は worldbox_mobs に空間ID前置キーで保存）。攻撃・接触ダメージとも地表と同じサーバー検証経路を空間対応させた。

## プレイヤー状態（HP・空腹・毒・死亡、2026-11-16 バッチ1）

- 状態の正は profile（bot_kv `worldbox_profiles`）の hp / hunger / status / vitalAt / respawn / restPoint / lastDamageAt / deaths。遷移規則は `web/lib/worldbox/vitals.ts`、入口は `/api/worldbox/vitals`（sync=時間精算 / damage=モブ接触 / set_bed=ベッド設定）。REST ハートビートには触らない。**vitals の書き込みはユーザー単位ロックで直列化する（2026-11-17 B3）**: sync / damage / set_bed / hazard（2026-11-17 に hazard も追加）は素の ownerKey（profile・roles ルートと同じ鍵）でロックを取り、ロック内でプロフィールを読み直してから保存する。roles ルートも同じく、set_role に加えて skill / revive もロック内で読み直してから保存する（revive は薬師側→対象側の順に別々のロックを取る二相方式で、対象の HP・pendingTeleport は対象のロック内でのみ書き、薬師側の付与は対象が蘇生しなくなった場合に巻き戻す。ロックの入れ子は作らない）。ロック外で読んだスナップショットで保存すると、並走する精算・被弾と上書きし合い、PvP の死亡通知（lastDeath / pendingTeleport）が消えてドロップした所持品が復活する。フィールド PvP の被害者側も同じ鍵（旧 `vitals-pvp:` は廃止）。攻撃者側のロックは取らない（相互攻撃で循環待ちになるため。攻撃力の読み取りは読み取り専用スナップショットで足りる）。守護への熟練付与は別ユーザーの書き込みのため、攻撃者のロックを出てから守護本人のロックで付与する。
- HP は 0〜100。空腹が 0 になると、0 が続く間 HP が減る。バイタル精算はサーバー時刻で行い、1回の精算で進める時間は30分が上限（長期離脱の即死防止）。
- 空腹の減少は活動連動（2026-11-16、ユーザー指摘「減るのが早すぎる」を受けて）: 放置では満腹→空まで約4時間（100/14400 /秒）とかなりゆっくりで、移動は放置の1.6倍、ダッシュは2.5倍と少し速くなる程度に収める。活動クラス（idle/move/dash）はサーバー側が判定する（クライアント申告の活動は使わない）: vitals の sync が本人の現在位置（プレゼンス→申告→セーブ）と profile に残した前回精算位置（vitalX/vitalY/vitalSpace）から平均速度を出し、0.3タイル/秒未満=idle、5.6未満=move、それ以上=dash とする（速度は 7 で頭打ち。空間が変わった窓・前回位置が無い窓は idle）。warm バフ（×0.6）は活動レートにも掛かり、飢えの開始時刻は窓内の実効レートで空腹が尽きる時刻として計算する。規則は vitals.ts（hungerDrainPerSec / classifyActivity / activityForWindow）が正。
- モブの接触ダメージはサーバー側が配置の再計算（実在）と距離（mobs ルートと同じ方式）を検証してから MobDef.attack を適用する。接触の発火間隔は1秒（クライアントの接触発火と一致、サーバー側でも lastDamageAt で担保）。クモ・クモの女王・ミツバチは毒を与えることがある。毒は3秒ごとに HP-2、30秒で切れ、解毒薬・薬草ポーション・はちみつティーで治る。毒の tick は毒の有効窓 [until-30秒, until] で数える（2026-11-16 夜通し S5）: 罠は精算なしで毒を付けるため vitalAt が古いままになり、vitalAt 起点だと古さぶん tick を過剰に数えて即死する。vitalAt は毒の起点にしない。
- 食事は空腹回復に加えて一部が HP も回復する（ItemDef.heal）。薬は新規アイテム「解毒薬」「包帯」＋薬草ポーション（heal / curePoison は ItemDef のデータ）。**食事効果の数式は vitals.ts の consumeEffect が正**（2026-11-17 に一本化: economy.ts の eatItem はアイテム消費と満腹ゲートだけを持ち、効果は consumeEffect 経由で適用する）。バフの持続時間はアイテム定義の buff.minutes が正で、vitals.ts の BUFF_DURATION_MS はカタログから導出する。満腹時の heal ゲートは役職込みの最大 HP（maxHpFor。守護は120）で判定する。
- 死亡時: 道具（category tool）は落とさない。それ以外の所持品は各アイテムの半分（切り捨て）を落とす（落とした分は消える。ドロップ実体の回収は将来）。HP は全回復、空腹は 50、毒は消える。
- リスポーン先の優先順（企画書 §9-2 の推奨初期値を採用）: ベッド（踏んだベッドが点になる）→ 最後の休憩地点（ロビー休憩ポッドで休むと戻り先のワールド座標を記録し、HP 全回復＋毒消去）→ 所属国のマーク（首都タイル）→ 原点スポーン。
- 表示: HP と空腹はステージ左上の常時バー（数値つき）のみ。毒は緑の「毒」ラベル。食事バフ（warm=「温かい食事」/ alert=「自然回復」）も毒と同格でラベル＋残り分を表示する（2026-11-17）。説明文は置かない。経済パネルにはバイタルを出さない（2026-11-17、ユーザー指示で撤去。ショップ利用中にバイタルは不要という判断）。
- フィールド PvP（2026-11-16、ユーザー決定「人を殴れるように」）: ワールド/洞窟/遺跡で他プレイヤーをタップしたときの振り分けは距離で分ける: 近接範囲内タップ=攻撃、範囲外タップ=カードを開く（パーティ招待の送信導線がカード内 UI だけのため、この振り分けで導線を維持する。ロビー・テント・ダンジョンは常時カードで攻撃不可。入口は vitals ルート action "pvp"、相手はプレゼンス ID で解決）。ダメージ式（playerAttack＋剣士倍率）・被弾クールダウン・スポーン保護・死亡処理（半分ドロップ＋リスポーン解決）はモブ戦と共通で、規則は vitals.ts の applyPvpDamage / pvpSpaceAllowed が正。距離は相手のプレゼンス実測へユークリッド 2.5 以内。被害者の死亡は被害者プロフィールに lastDeath（死亡通知）＋ pendingTeleport（リスポーン地点）を対で残し、被害者の次回 sync がモブ死と同じ死亡フローで配送して消す（即時通知の仕組みは作らない）。闘技場のターン制決闘（pvp.ts）とは別物。

- 冒険役職は国の役職とは別軸で、本人がギルドボード「冒険役職」タブで選ぶ職業（自由人＋剣士/守護/斥候/採掘者/薬師/テレポーター）。変更はギルドボード前でのみ（station "guild" 検証）、インスタンス内は不可。規則は `web/lib/worldbox/roles.ts`、入口は `/api/worldbox/roles`。profile に role / rolePicked / mastery（役職ごとの `{xp}`、切替えても保持）/ skillAt / tauntUntil / reviveMark / pendingTeleport を保存する。

- 熟練ランクは XP 閾値 [0, 30, 80, 160, 300] で 1〜5。XP の出所は専門行為（剣士=撃破+3、守護=味方を守った被弾+2、斥候=遺跡の宝箱+4/罠+3、採掘者=鉱脈+1（希少以上+4）、薬師=回復アイテム使用+2/蘇生+10）。技の使用・成功にも付与する（2026-11-17）: 守護=挑発の使用+2、薬師=ヒーリングゾーンの詠唱+2、技による撃破は役職を問わずその役職へ+3。

## パーティとダンジョン（2026-11-16 バッチ5）

- パーティはダンジョン入口の前でだけ編成する場面単位の集まり（ロビー永続化なし）。リーダー+最大3人、ユニオン跨ぎ可、ソロ可。招待はリーダーが近くのプレイヤーをタップ（プレゼンス検証7タイル、60秒で失効）。解散はリーダー退出/全員退出/ダンジョン終了。状態は bot_kv `worldbox_party`（本体+メンバー/招待の索引キー）。入口は `/api/worldbox/party`、規則は `web/lib/worldbox/party.ts`。
- パーティ退出時のセッション後始末（2026-11-17 是正）: party ルートの leave は、ダンジョンセッションの退出者を departed に入れ、解散（リーダー退出）時はセッション自体を削除する。セッションは partyKey（パーティ ID）に紐づくため、放置すると中にいる全員の操作が no_session になり、セッションも消えずに残る（孤児化）。セッションへのアクセスを失う人（退出者本人は常時、解散時は中にいる全員）は pendingTeleport で入口前へ戻す（宛先はセーブの worldReturn を優先し、配送とプレゼンス/セーブの整合は vitals sync が担う。既存の配送予定がある場合はそちらを優先）。招待の accept は、既に別のパーティに所属している場合は `already_in_party` で拒否する（所属の索引だけ上書きすると旧パーティに幽霊メンバーが残り、人数とセッションに数えられ続けるため。所属の変更は leave を明示的に挟む）。
- ダンジョンの空間 ID は既存形式 `dungeon:<入口x>,<入口y>:<層>`（層は0始まり）を踏襲し、パーティ分離はセッションキー `#<partyKey>` とプレゼンスの party フィールドで担保する（SPEC の `dungeon:<パーティID>` 形式からは意図的に逸脱。分離と破棄の意味論は保持）。セッションは bot_kv `worldbox_instances` の `<1層目空間ID>#<partyKey>`、ルートは全て個人別（宝箱の取得記録も個人キー）。
- 生成は決定的（52×52、4層=3フロア+ボス層、3×3部屋+通路、BFS最遠=ボス部屋）。各フロアに番人（ghost）がいて倒すと `dungeon_key` を落とし、境界通路の鍵扉を開ける（番人は技の対象のままで、技で倒した場合も鍵は落ちる。2026-11-17 是正: 従来は通常攻撃の経路だけが鍵を落とし、技で倒すと再出現まで扉が開けられなかった）。フロアボスを倒すと階段が開く（サーバー側でも前層ボス撃破を攻撃ゲートとして検証）。ボスは入口ごとに決定的: 中層は ogre/spider_queen 交代、最下層は ogre/spider_queen/dungeon_dragon の3種から決定的選択。
- モブ HP はパーティ人数で ×1.0/1.6/2.2/2.8（攻撃力は不変）。ダンジョン内の技はフロアボスを対象にしない（進行登録は通常攻撃の経路に一本化）。
- 熟練ゲートをサーバーでも検証する: フロア2以降の攻撃・宝箱・扉はパーティ内にランク2+が1人、ボス層はランク3+が1人必要（partyGateSatisfied、members の profile から判定）。
- 全滅（全員 dead/departed）でインスタンスは閉鎖し、途中離脱は進行破棄。ダンジョン内死亡のリスポーンは入口前。ボス宝箱はボス撃破必須で罠無効（通常宝箱の罠は HP-10 のみ）。
- クリア報酬 `dungeon_clear` = 500（暫定）は週1回・その場の生存メンバー全員へ。earn ホワイトリストに TS/Python 両側で追加済み。ボス素材は最上位の鍛冶レシピに接続（dragon_scale→ミスリル剣、ghost_tear→ゴーストランタン）。

## ユニオン戦争と繁栄ランキング（2026-11-16 バッチ7a）

- レイド宣言はギルドボードの前で王/大臣だけが行う（station "guild" 検証、役職の操作と同じ場所制約）。宣言で即戦争状態（24時間）。1国が同時に関わる戦争は1件まで。宣言は1国あたり24時間に1回まで（早期終結してもクールダウンは宣言時刻から24時間）。
- マーク = 首都タイル。戦争中、攻撃側の国民は防衛国の首都の2タイル以内からマーク HP（100）を削れる（1回 -10、個人クールダウン10秒）。防衛側の国民は同じ範囲から修復できる（1回 +10、個人クールダウン30秒）。位置・所属・クールダウンはすべてサーバー検証（プレゼンス → 報告位置 → セーブの順）。
- マーク HP が 0 になると防衛国は解散し（国と所属を消す）、戦争は攻撃側の勝利で終わる。期限（24時間）を過ぎた戦争は引き分けで終わる。戦争の記録（勝敗・履歴）は bot_kv `worldbox_wars`（キー "state"）に持ち、履歴は最新20件まで。
- 他者ブロック破壊ルール（企画書 §9-3 の推奨初期値）: 平時は他者のブロックを掘れない。戦争状態のときだけ、攻撃側の国民が防衛側の首都から12タイル（チェビシェフ）以内にある防衛側国民のブロックを掘れる。掘ったブロックは掘った者の所持品に入る（略奪ルールはこれに一本化）。判定は tiles ルートが戦争状態と所属を引いて行い、純粋ロジックは `web/lib/worldbox/war.ts` の `canBreakOthersBlock` が正。**期限の伝播（2026-11-17 是正）**: expireWars は war ルートでしか走らないため、tiles ルートは `canBreakOthersBlock` に現在時刻を渡し、`warLiveAt` で期限切れ（status が "active" のまま未精算）の戦争を不可として扱う。
- **戦争 state の直列化と解散の回復（2026-11-17 是正）**: `worldbox_wars` の "state" は単一キー RMW で複数ギルドが触るため、war ルートの読み書き全体（期限精算・宣言・攻撃・修復）を `withWarLock`（state 全体の直列化）で包む。マーク破壊による解散は「戦争の保存→解散」の順で、解散の保存が失敗しても、閉じた戦争（attacker_win）と残った防衛国は次回リクエストの `settleDisbands` が冪等に解散させる（戦争終了より後に建国された同 ID の国は対象外）。
- コインの流れは無い（略奪はブロック現物のみ）。戦争で earn/spend は作らない。
- 繁栄ランキングは繁栄度順（同値は建国が早い方を上位に）。入口は `/api/worldbox/war`（GET で戦争・履歴・ランキング・自分の所属を返す）。表示はギルドボード「戦争」タブ（マーク HP バー・攻撃/修復・宣言・ランキング・戦績）。**マークの世界地図表示（2026-11-17 是正）**: 戦争中の国のマークは世界地図でも櫓に赤い枠（脈動）が出る。防衛側は国名の下にマーク HP バーも出す（攻撃側は自国マークが削られていないので枠だけ）。データは nations 応答の `warMarks`（war.ts の `warMarksByNation` が正、期限切れは warLiveAt で除外）で、一覧に出ている国の分だけ付ける。
- バッチ7の残り（次バッチ以降）: ギルドショップ（出品/売上/手数料5%）。ショップ在庫の日次変動は PR #966 で出荷済み。闘技場PvP＋大会・カジノ大会はバッチ7c で出荷済み（上記「闘技場PvP」「闘技場大会」「カジノ大会」参照）。

## ソーシャル（2026-11-16 バッチ6）

- ネームプレートは「ユニオン色の枠プレート」に統一する: 中身は Discord マーク（描画）+ 冒険役職シンボル + 名前 + 熟練ドット（ランク2以上）。プレゼンス GET が role/rank/party を落としていた問題も合わせて修正（WS 中継と同じフィールドを REST でも返す）。

- Discord 連携の円滑化（2026-11-16 バッチN2）: **チャンネル ID の手入力は廃止**。Bot のワーカー（core/general/circulation/worldbox_discord.py、起動時＋5分間隔）が、国が存在する各ギルドについて「Bot が閲覧・送信できるテキストチャンネル一覧（上限100）＋そのギルドのグローバルチャット連携チャンネル」を bot_kv `worldbox_discord_directory`（キー = ギルド ID）へ公開する。Web はこのディレクトリのチャンネル名から選ばせる（lib/worldbox/discord-directory.ts）。連携設定は `{ mode: "global" | "channel" | "none", channelId }` 形式（lib/worldbox/chat.ts の parseUnionChatSettings が正）で、旧形式 `{ chatChannelId }` は mode "channel" として移行読込する。専用チャンネルはディレクトリに載っているものだけ設定でき、ディレクトリ未取得のギルドは「Discord側の準備待ち」表示にして ID 入力には戻さない。送信の宛先は mode で解決する（global → ディレクトリの globalChatChannelId、channel → channelId、none → 送らない）。**受信（Discord → ゲーム内）も実装済み**: 連携チャンネルへの通常ユーザー投稿を Bot が拾い、ユニオン掲示（`worldbox_union_board`、キー `union:<ギルドID>`）へ source "discord" で追加する（名前 = Discord 表示名、本文120字上限、メンション無効化相当のサニタイズ、保持24時間・50件は掲示の既存規則）。ループ防止: Bot 自身・webhook の投稿は拾わず、送信リレーの文面（`**名前**（WORLD BOX ユニオン）: 本文`）も拾わない。global 流用時の受信対象は「そのギルドの当該チャンネルへの直接投稿のみ」で、他サーバーのグローバルチャット横断分は webhook 投稿なので対象外。**ディレクトリ公開ループの無言死防止（2026-11-17 夜通し B5、構造問題#7）**: チャンネル一覧の取得失敗はワーカー内で吸収して次周期に再試行し、ループ本体も #960 方式で try/except してある（`worldbox_discord_loop`）。受信リレーの掲示 RMW はエントリ ID が `discord:{message_id}` で決定的なため同一メッセージの再処理で重複しない。**並行処理の直列化（2026-11-17 是正）**: ワーカーは掲示 RMW をギルド単位の asyncio ロックで直列化し、Web 側も `appendChatMessage` をリスト単位の `withUserLock` で直列化したため、各プロセス内の同時投稿では欠落しない。bot_kv に CAS が無いため、Bot リレーと Web 投稿がプロセスをまたいで同一瞬間に書く場合の窓だけが残る。

## 機械基盤と自動収穫機（バッチ10a、2026-11-16）

- 装置の土台は `web/lib/worldbox/machines.ts`: 装置 = 設置ブロック（facility）に
  紐づく DeviceProgram（trigger/action/intervalSec/enabled）と実行状態。
  状態は bot_kv `worldbox_machines`（キー "x,y"、収納コンテナと同じ方式）。
- プログラムは共有コード（"WB1." + base64url JSON）で書き出し/取り込みでき、
  他人の作った装置設定をそのまま使える。組み込みプリセット3種を用意。
- 最小の実働装置「自動収穫機」（furniture、800、レシピ: 鉄インゴット3+木4）:
  隣接8タイルの自分の畑で育ち切った作物を、評価間隔ごとに自動収穫して
  装置内バッファへ貯める。評価は遅延式（GET/POST のたびに解決）で常駐
  ループは持たない。回収は所有者がパネルから。バッファが残っている間は

- 装置のタップは採掘ではなく専用パネルを開く（自分のものだけ）。

## ギルドショップ（バッチ7残件、2026-11-16）

- 区画はロビー屋台グリッドの6つ（カウンター中心が GUILD_PLOT_ANCHORS）。
  状態は bot_kv `worldbox_guild_shop`（キー "state"）、検証と遷移は
  `web/lib/worldbox/guild-shop.ts`、ルートは全体ロックで直列化する。
- 登録/撤去は国王・大臣のみ。登録料 500（spend guild_plot_fee、決定的 ID
  gshop-fee-<discordId>-<seq> で冪等）。撤去時は残りの出品を売り手へ返却。
- 出品は所属員のみ（アイテムはエスクローでプロフィールから引く、1区画12件まで）。
  購入は区画カウンターから 3.5 タイル以内（プレゼンス/セーブ検証）。
  購入 spend guild_shop_buy、売り手 earn guild_shop_sale（ホワイトリスト済み）、
  オプ ID は gshop-buy-/gshop-sale-<listingId>-<累計販売数> で冪等。
- 手数料は区画の国の税率（国家設定、既定 5%）: 売り手の取り分は
  floor(価格×個数×(1−税率)) で、差額は積まない（= 国庫シンク相当）。
  税額は国家設定の taxCollected へ表示用に累計加算する（バッチN1）。
- 地図表現（2026-11-17 是正）: 区画を借りるとロビー地図のカウンター上にギルド名が表示される（首都マーカーの国名と同じ描き方）。状態の追随は relay watch の `worldbox_guild_shop` poke（kind "guildShop"、全体合図）→ クライアント取り直しで、開いているギルドショップパネルも同じ合図で取り直す。GET 応答の出品には閲覧者本人の出品かを示す `mine` が付き、パネルの「下げる」表示条件はサーバーの unlist 権限（出品者本人 / 区画ギルドの王・大臣）と一致する（売り手の生キーは従来どおり出さない）。

## プレゼンスの P2P 化（検討中・未決定）

- 背景: ハートビート1秒＋ポーリング2秒の輸送では他プレイヤー表示の滑らかさに限界があり、ユーザー指示で P2P（WebRTC DataChannel）も検討対象に入った（2026-11-15）。ただしサーバー権威は維持する。
- 役割分担: P2P は「見た目専用」。他プレイヤーの高頻度な位置・向き・歩行位相だけを、近くのプレイヤー同士で直接流す（対象は近距離のみ、ピア数は上限を設ける）。
- サーバーが正のままのもの: 自分の位置の確定（ハートビートは残す）、station 検証、steal、チャットの到達判定、経済、セーブ、タイル・建物。P2P で受けた情報を根拠にサーバー状態を変えることは一切しない。
- チート対策:
  1. 署名付きスナップショットをアンカーにする。サーバーがプレゼンス応答に署名を付け（秘密鍵はサーバー側のみ、公開鍵をクライアントへ同梱）、P2P の自己申告位置は、直近の署名済み位置から最大移動速度（ダッシュ・水泳の上限＋余裕）で届く範囲内へクランプする。範囲外は捨てる。
  2. P2P 更新には単調増加の連番と送信時刻を持たせ、古いもの・未来すぎるもの・速度超過は破棄する。外挿はサーバー側と同じ上限（2秒）まで。
  3. P2P で話せるのはサーバーのプレゼンス名簿にいる相手だけ。名簿から消えたら即切断する。
  4. 表示にしか効かない構造にする。仮に表示をごまかせても、盗み・売買・チャットの可否は全部サーバー側の位置で判定されるため、実害が出ない。
  5. シグナリングは既存のプレゼンス API 経由（bot_kv で offer/answer/ICE を受け渡す）。TURN は置かず、繋がらない相手は従来のポーリング表示へフォールバックする。
- 段階導入: まず「P2P は表示補完のみ・サーバーポーリング併用」で入れ、負荷と体感を見てからハートビート間隔を広げるか判断する。
