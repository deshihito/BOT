# WORLD BOX 共有ノート（全 Muse 必読）

AGO WORLD BOX（web/app/games/worldbox）に関わる作業をする Muse は、**作業前にこのファイルを読むこと**。複数の Muse が並行して触るため、決定事項はここに集約する。新しい決定が出たら、実装と同じ PR か直後の PR でここを更新する。

最終更新: 2026-11-16

## 製品の前提

- AGO WORLD BOX は「ゲームの1つ」ではなく AGO のメタバース基盤。ワールドは単一の共有ワールドのみ。
- Discord との融合が核: プレイヤーの本人性・所属・経済は全部 Discord / AGO BOT 本体に紐づく。
- カタログ上は独立ジャンル「WORLD BOX」（web/lib/games-catalog.ts の GAME_GENRES 先頭）。

## 確定した決定（覆す場合はユーザー確認が必須）

### 世界と移動
- 見下ろし型。マップはチャンク式（座標＋固定シードの純関数生成）で実質無制限。北に雪原バイオーム。初回スポーンはランダムな陸地。所属国のマークへファストトラベル可。
- 同時接続プレゼンスあり（空間: world / lobby で分離）。他プレイヤーは向き反転＋補間移動で描く（瞬間移動させない）。
- プレゼンスの滑らかさは P2P 化せず、フレーム補完（スナップショット補間）で対応する（担当: deshihito 側）。SSE プッシュ化案は採用しない。
- テントは入れる室内空間（2026-11-15）: テント（facility）を置いて踏むと専用空間 "tent"（13×10、lib/worldbox/tent.ts、LobbyData と同形）へ入り、出入口パッドで戻る。内装には作業台とかまど（station smith）があり合成できる。空間はセーブ・プレゼンス・中継・ステーション検証すべてで world/lobby と並ぶ第3の空間として扱う。ステーション検証（station-online）はプレゼンスが無い/古い場合にセーブ（ワープ時の空間と入口位置）で代替する。
- プレゼンス中継は WebSocket 化した（2026-11-15、ユーザー決定）: 本番の起動エントリは web/realtime-server.js（standalone の server.js を内包するラッパーで、通常 HTTP は内部ポートの Next へ素通し、/api/worldbox/realtime だけ中継）。中継の純粋ロジックは web/realtime/relay-core.js、接続認証は短期署名トークン（POST /api/worldbox/realtime-token、セッションと同じ鍵）。REST プレゼンス（bot_kv）はフォールバックとして併存し、中継が落ちてもポーリングで遊び続けられる。位置は中継でも申告制のまま（整形と鮮度管理のみ、実害のある検証は各 API 側）。
- 注意（2026-11-15 実害発生→対処済み）: WS 接続中はクライアントが REST ハートビートを止める作りだったため、bot_kv プレゼンスが凍結し、bot_kv プレゼンスを位置の正にするサーバー検証（カジノ・ステーションゲート・ギルドボード・モブ攻撃の距離）が全部古い位置/不在で判定して死んだ（カジノで実害確認）。対処: クライアントは WS の有無と独立に REST ハートビートを併送し bot_kv の鮮度を保つ（heartbeatTick の lastRestHeartbeatAt、間隔は移動中500ms/静止2s）。モブ攻撃には申告位置フォールバックも併設（mobs ルート）。**REST ハートビートはサーバー検証の正なので止めてはいけない。**
- スタミナ制: ダッシュ（モバイル=スティック強倒し、PC=移動キー2度押し）、水泳可（水中で切れたら最後の陸へ帰還）。ゲージはゼルダ式の円形をキャラ左上に。自動回復。
- ロビーは別空間（ファストトラベル往復、元の場所に戻る）。外形は図形の和集合。中央広場に掲示板・噴水・ワープ、左=ショップ街（あごむに店員）、右=カジノ、上=闘技場、下=鍛冶屋、北東=銀行、南西=休憩。ショップ翼2階=ギルドショップ区画。

### 国（ユニオン）
- 国 = Discord サーバーそのもの。建国できるのはサーバーオーナーのみ、国名 = サーバー名。市民 = そのサーバーのメンバー、役職は Discord 権限から導出（オーナー=国王、ADMINISTRATOR=大臣）。
- **国判定を持つのはユニオンマーク（建国の印）のみ**。首都の概念はマークに統合。マーク破壊 = レイド判定（将来の戦争レイヤーのトリガー）。
- 国は「所属区分」だけ。それ以外（建築・経済・作物）は全部ユーザー単位。ユニオン所有という概念は持たない。

### 建築・農業（プレハブ設置は禁止）
- 「家を設置」「畑を設置」は**やらない**。家はブロックを積む自由建築、畑は地面を耕して好きな作物を植える。
- ブロックは種類と耐久を持つ（ユニオン防衛の基礎）。入手はショップ購入＋マップ採掘の2ルート。
- 基本素材の直接設置（2026-11-15）: 木材・石材は素材のままでは置けないのが「設置できない」の実態だった（選んでもハイライトが出ず「そこではできない」だけ出る）。ItemDef.placesBlock で素材→ブロックの対応を持ち、木材はオークの原木・石材は石ブロックとしてそのまま置ける。消費は素材側、描画・耐久・掘り返し回収はブロック側の定義に従う。
- 旧来の設置型 buildings（house/field/tower のプレハブ）は廃止し、コードを完全撤去した（2026-11-16、ユーザー決定）: lib/worldbox/buildings.ts・buildings-online.ts・/api/worldbox/buildings は削除済み。**復活させない。** 繁栄度は国民数 × 5 のみ（建物の算入は廃止）。≡ メニューの「建築」パネルも中身が建物だけだったため導線ごと撤去した。bot_kv（worldbox_nations 名前空間の "buildings" キー）の既存データは残置するが、コードからは参照しない（到達不能）。

### 経済（案B ブリッジが唯一の正）
- 通貨は AGO コイン本体のみ。**Web 側で残高を直接増減しない**（ミント禁止）。
- Web は bot_kv 名前空間 `worldbox_economy` にオプを積み、Bot 側ワーカー（core/general/circulation/worldbox_economy.py）が pay_house / ウォレット / transfer_coins で適用する。earn はバンクロール（プール+国庫）の利益分のみ（Plan A）。
- profile 内の独自コイン（profile.coins）は廃止済み。読込互換のためだけに残っている。**復活させない**。
- オプ種別: spend / earn / transfer / steal / gamble。earn 理由はホワイトリスト制。
- カジノ（ロビー右翼）は実働施設: スロットマシンの前=スロット、カジノテーブルの前=ルーレットで実際に賭けられる。位置はサーバー側がプレゼンスで検証する。1プレイは gamble オプ1件（amount=ベット、payout=確定配当）で、ワーカーがベット引き落とし→配当（利益分は pay_house、負けは add_loss 還流）を原子的に適用する。抽選は Web サーバー側。ベット上限はブリッジの金額上限に一致（独自上限なし）。
- カジノのゲームは Bot 側ギャンブルと Web /games の資産を移行して増やす（2026-11-15 追加分）: テーブル=ダイス（原典 play_dice、当たればベット×範囲）/ ブラックジャック（web/lib/blackjack.ts の純粋ロジック、3:2・ダブルあり）/ ダブルアップ（原典の倍率×1.6・内部モード遷移）、スロットマシン=セブンスロット（原典 slot7 の状態遷移・確変・天井・6ペナルティを移行）。セッション型は「開始時に spend で先払い → 終了時に prepaid の gamble 1件で精算」が決済の型。精算オプは先払いが done になってから作り、先払い失敗のセッションは無効化する。セッションは1人1つまで、30分で期限切れ（未使用分は返金）。内部状態（確変・six カウンタ・内部モード）は bot_kv worldbox_casino にユーザー単位で永続化し、slot7 とダブルアップで共有する（原典と同じ）。適応: slot7 の 66666 全額没収はブリッジに手段がないため採用しない（そのスピンは報酬0）。
- 精算の冪等性と処理速度（2026-11-16、二重精算と滞留の実害を受けて）: パネルは GET を3秒間隔でポーリングし、各リクエストが精算を走らせるため、カジノルートは同一ユーザーのリクエストをプロセス内ロックで直列化し、精算オプは決定的 ID（`settle-<先払いオプID>`、BJ 返金は `refund-…`、slot7 ペナルティは `penalty-…`）で積んで既存があれば作り直さない。**精算オプにランダム ID を使ってはいけない**（二重払いの温床）。Bot 側ワーカーは 5 秒間隔・最大100件/回で回し、claim の失効は90秒。wallet 取得の例外はワーカー内で吸収する（外に出すと tasks.loop ごと止まって経済処理が無言で死ぬ）。
- 冪等性の総点検と横展開（2026-11-16 夜通し S1）: カジノ以外の経済経路にも同型の問題（ロック無しの read-modify-write ＋ ランダム ID）が残っていたため横展開した。共有基盤は `web/lib/worldbox/user-lock.ts` の `withUserLock`（キー単位のプロセス内ロック）と `economy-bridge-online.ts` の `enqueueEconomyOpOnce`（決定的 ID の冪等登録、既存があれば作り直さない）。適用先: 闘技場（ユーザー単位ロック＋賞金は `prize-<参加費オプID>`）、プロフィール売買・合成等（ユーザー単位ロック。二重売却＝コイン生成を防止）、ギルド依頼（依頼全体を固定キーで直列化＋ `escrow-/reward-/refund-<依頼ID>`。納品×取消の競合で報酬と返金が両方払われるのを防止）、広場の噴水・休憩（ユーザー単位ロック。残高検証のすり抜けとクールダウン競合を防止）、インスタンス（空間単位ロック＋遺跡の初回開封 earn は `ruinsCompleteOpId` = `ruins-done-<入口x>-<入口y>-<Discord ID>`）。**新しい経済経路を足すときは、状態の RMW とオプ登録を必ずロックで直列化し、「1回だけ払う」オプは決定的 ID ＋ enqueueEconomyOpOnce で積むこと。** 送金（economy ルート）は1リクエスト＝1回の意図的な送金でサーバー側の繰り返し契機が無いため対象外（記録済み）。
- 闘技場（ロビー北）は実働施設: 階級（スライム/ゴーレム/ワールドドラゴン）を選んで参加費（spend arena_entry）を払い、ターンバトル（たたかう/強攻撃/まもる）。攻撃力は所持する最良の剣の tier で決まる（素手8 + tier×4）。勝利で賞金（earn arena_prize、Plan A 内）。セッションは bot_kv worldbox_arena、1人1つ、10分で期限切れ（参加費は戻らない）。参加費のオプが done になるまで対戦は始まらない（カジノの先払いと同じ型）。
- 噴水と休憩ポッドも実働: 噴水はコイン投げ（spend 10, fountain_offering）でスタミナ全回復＋25%で素材1つ。休憩は無料でスタミナ全回復（3分クールダウン、bot_kv worldbox_rest）。スタミナはクライアント側の状態なので、サーバーは費用・場所・クールダウンを検証し回復可否だけ返す。ショップ/銀行/鍛冶屋は経済パネル（施設タブ）で実働済みで、ステーションチップからも直接開ける。
- ショップの品目は店員ごとにジャンル分け（lib/worldbox/shops.ts）: 道具屋=道具／建築屋=ブロック／家具屋=家具／食料屋=食事・作物／種・素材屋=種・素材／鍛冶屋=合成品・特殊。アイテムカテゴリは各ジャンルへちょうど1回割り当て、ロビーの全 shop オブジェクトが genre を持つ。購入はサーバー側でも genre を検証し、違う店の品目は買えない（409 wrong_shop）。売却は shop / smith どちらでも可（ジャンル不問）。
- レア品は店で販売しない（2026-11-16、ユーザー決定）: 特殊カテゴリ全品・道具の tier 4（ミスリル4種）・宝石ブロック4種（ダイヤ/エメラルド/ルビー/サファイア）の計26品は、どの店の品目にも載せない（shops.ts の isShopExcluded、購入は 409 not_sold）。入手は合成・ドロップ・探索のみ。売却はレア品も従来どおり可。宝石の素材・鉱石ブロック・合成品の高額品は販売対象のまま。
- 労働は廃止（2026-11-16、ユーザー決定）: 経済パネルの「労働する」ボタンを撤去し、profile ルートは action "work" を常に 409 work_disabled で拒否、earn の許可リスト（Web 側 EARN_REASONS と Bot 側ワーカーの同集合）からも "work" を除外した（新規の work オプは作れず、滞留分もワーカーが invalid_reason で落とす）。過去オプの parse と純粋ロジック（economy.ts の doWork）は履歴互換のため残す。steal 廃止（PR #940）と同じ方式。
- カジノの演出はドーパミン濃いめが方針（lib/worldbox/casino-fx.ts）: 配当倍率で階級 0〜4 を分け、紙吹雪・カウントアップ・フラッシュ・シェイク・効果音（lib/sfx）の強さを階級連動にする。スロットはリールが1つずつ止まり、先2つ一致でリーチ（3つ目が長く回り赤く光る）。セブンは数字ロール＋確変中は金色パルス、超JACKPOT は最高階級。演出はクライアント側だけで、抽選・決済のサーバー仕様は変えない。
- カジノは1台1ゲーム（タブ式は廃止）: 北列=スロット台×3＋セブン台×3、中央=ルーレット/ダイス/ブラックジャックの専用テーブル、南列=ダブルアップ台×3＋スロット台×1。各機器は専用スプライト（slot7_machine / roulette_table / dice_table / blackjack_table / double_machine）で、機器判定 casinoMachineNear がゲームを返す。パネルは立っている機器のゲームだけを表示し、API も開始・操作とも機器一致を要求する。ピアノは station を外した（カジノ判定だけ出て遊べない罠だった）。

### 行動の場所制約
- 購入はその店の場所でのみ（アイテムショップ等）。合成は作業台、精錬はかまど、というように行動は施設に紐づける。
- どこでもできるのは移動・採取などの基礎行動のみ。制限はサーバー側でも位置検証する。
- 場所検証はプレゼンス（サーバー側の現在位置）＋ stationNear で行う（カジノと同方式、lib/worldbox/station-online.ts）。クライアントは「いる施設のタブ／ボタンだけ出す」で表示を一致させる。
  - 売買 = ショップの前（station "shop"、ギルドショップ区画のカウンターも同じ）。経済パネルのショップタブとかばんの売却はショップの前でのみ表示（旧: ロビー空間ならどこでも、PR #886 の緩い制限は置き換え）。
  - 合成 = 鍛冶屋の作業台の前（station "smith"）。≡ メニューの空のクラフトパネル（器だけ）は廃止し、合成は経済パネルの合成タブに一本化。
  - 送金 = 銀行の前（station "bank"）。残高・履歴の閲覧は従来どおり。
  - 掲示板の投稿 = 掲示板の前（station "board"）。閲覧は従来どおり。
  - 依頼の投稿・納品・取消と役職の操作（建国・参加・離脱）= ギルドボードの前（station "guild"）。閲覧は従来どおり。
  - カジノ = 機器の前（機器種別まで検証、既存）。
- ジョイスティックは左下の固定式（lib/worldbox/stick.ts）。タッチした場所に基点が出るフローティング式は、ブロック設置・採掘のタップと干渉するため禁止。スティック操作は固定基点の円の中から始まったタッチだけ。

### アイテム・インベントリ
- 基礎設計は「入口としての物量」優先。カタログ（web/lib/worldbox/items.ts）はデータ駆動で大量に持つ。追加はデータのみで。
- インベントリ 5 枠 = すぐ使う手持ち（ホットバー）、ストレージ 10 枠 = 持ち歩く裏の手持ち。
- 収納コンテナ（2026-11-16）: 樽（10枠）・宝箱（15枠）は設置して物を収納できる（lib/worldbox/containers.ts）。中身は bot_kv `worldbox_containers`（キー "x,y"）にタイル単位で持ち、開ける・出し入れできるのは所有者だけ（他人は 403）。中身が入っている間は回収（mine_block）できない（409 not_empty）、空にすると回収と同時に状態も消える。出し入れはインベントリ整理と同じタップ式（持つ→置く/合体/入替）。
- 道具: ツルハシ（岩）、斧（木）、剣、クワ（耕す）。ティアあり。

### 演出（アニメーション/モーション/パーティクル）
- 演出の計算は `web/lib/worldbox/fx.ts`（純粋ロジック）に集約する。行為の成功→ `fxEventsRef` 経由で描画ループが粒・揺れ・出現ポップに変換する配線が正。
- パーティクル: 同時上限 FX_CAP=260、1バースト最大26粒、寿命は短く（0.16〜0.9秒）。色は明暗を混ぜて背景を選ばない。形は chip/spark/drop/ring/puff/leaf/snow/glow。
- 行為の払い戻し: 伐採=木片、採掘=石片、耕す=土塊、植える=若葉、収穫=実りのきらめき、設置=土煙+出現ポップ、建築/破壊=破片+揺れ、入出水=水滴、ダッシュ=風の筋、ワープ=立ち上る光。タップへの即時応答として道具スイング+風切りを出す（結果の粒は成功時）。
- 環境粒: 雪原=雪、森=落葉、夜=蛍、それ以外=花粉。移動の副産物として足元に土ぼこり/水しぶき。
- 揺れはワールドのみ（ロビーはピクセル固定のため揺らさない）。`prefers-reduced-motion` では粒を絞り揺れを切る。
- モブ演出の語彙（第2弾）: 出現=`spawn`（煙と光が立ち上る）、被ダメージ=`hit`（赤/白/暗色の火花、寿命0.18〜0.38秒）、死亡=`death`（大きめの破片+煙、描画ループ側で小さな揺れ併用）。生成は `spawnMobFx` に集約し、モブの占有サイズ（1〜20マス）で粒数（最大2.6倍）・粒サイズ（最大2.2倍）・散らばりをスケールする。FX_BURST_MAX と FX_CAP の上限は常に守る。出現は出現ポップも併用可。
- 空振り（行為の失敗）は粒を出さず、風切りだけを薄く（WHIFF_ALPHA_SCALE=0.45）・細く・道具アイコンなしで出す。成功の粒は成功時にだけ出す原則は維持。
- 天候は決定的サイクル（fx.ts の `weatherAt`、WEATHER_PERIOD_SEC=360秒区間のハッシュで雨/晴れを決定、雨の比率は約35%）。サーバーを介さず全クライアントで一致させる。環境粒の優先順位は 雪 > 雨 > 森 > 夜 > 花粉（雪バイオームでは雨でも雪）。雨は spark の筋で速く落ちる。
- 時間帯の名前は fx.ts の `phaseKind`（dawn 0.18〜0.30 / day 0.30〜0.68 / dusk 0.68〜0.86 / night それ以外、daynight.ts の nightAmount と整合）。時間帯が切り替わったフレームでは新しい種類の環境粒を数粒追加で出す。

### 音響（BGM/SE、2026-11-15）
- 音響の基盤は `web/lib/worldbox/sound.ts`（譜面・対応表は純粋ロジック、再生は Web Audio 合成のみ）。カジノパネル内の効果音は従来どおり `lib/sfx`（カジノ演出の階級連動が正）。
- **opus っぽい音は禁止**（ユーザー指示）: 音声ファイル（.opus/.mp3 等）を使わない。BALKU 式のサイン波パッド wash＋ローパスで曇らせる作りも WORLD BOX では使わない。BGM は短く減衰する打鍵音（マリンバ風プラック）＋細い矩形波＋ノイズハットで組む決定的ループ、BGM バスにローパスは掛けない。
- BGM は場面で切り替わる（`bgmSceneFor`: カジノ > 屋内（ロビー/テント） > 夜 > 昼）。譜面は32ステップ固定で乱数生成しない。夜はリード疎ら・ハット/キックなしで一番静かにする。
- SE は fx のバーストと同じイベントから出す（`seForFxBurst`、死亡=kill・出現=poof）。素材音（木/石/土/水）を作り分け、階層ゲインは sfx.ts と同じ配分（撃破 > ヒット > 行為 > 移動 > 足音）。足音などには連打防止の最小間隔がある。
- AudioContext は最初の操作（pointerdown/keydown）で解錠する。設定は localStorage `worldbox-sound`（BGM/SE 個別）、切替は ≡ メニュー内（ボタンは押したときの動作を示す）。非表示タブでは BGM を止める。

## 拡充カタログ・マップロジック（2026-11-15 追加）
- アイテムカタログは 323 種（素材43・ブロック76・種26・作物24・食事52・合成品31・家具37・特殊18・道具16）、レシピ159種、作物定義26種、アイコン306種。追加は items.ts へのデータ追加のみで、アイコンは public/img/worldbox/items/<id>.png + ITEM_ICON_IDS に登録する。
- バイオーム/チャンク/構造物の基礎ロジックは web/lib/worldbox/maplogic.ts（座標から決定的。biomeAt / chunkOf / structuresForChunk / findLandSpawn）。構造物はスーパーセル方式で同種の最小間隔を保証する。入口系は「1マス→別枠マップ（cave/dungeon/ruins）」で、中身は洞窟=希少鉱物・遺跡=宝箱+罠・ダンジョン=強敵。
- 特殊オブジェクトは web/lib/worldbox/objects.ts（採取/鉱脈/宝箱/入口/温泉/魚影など22種、決定的配置＋ルート＋再出現）。モブは web/lib/worldbox/mobs.ts（48種、バイオーム・時間帯・ドロップ表。ダンジョン専用含む）。
- モブのサイズは 1〜20 マスで規定する（size×size 占有、アンカー中心）。サイズ帯: 1=小型 / 2〜3=中型 / 4〜6=大型 / 7〜12=巨大 / 13〜20=超巨大。大型（size>=4）はチャンク密度で出さずスーパーセル配置（セル一辺 size×2 チャンク、同種は最大1体）で疎らに置く。
- フィールド戦闘（2026-11-15 実働化）: モブは地表に実体として出る。個体は「種@アンカー」で識別し、HP と死亡（再出現15分＋個体キー決定的な追加遅延0〜10分、combat.ts の mobRespawnDelayMs）だけを bot_kv `worldbox_mobs` に持つ。攻撃はモブのタップ（タイル行為より優先、クールダウン350ms）。剣を選択中は照準方式でなく範囲方式（ユーザー指摘で変更）: タップで常に振り、攻撃範囲内のモブに当たる（対象は attackTarget が「タップを含む個体→近い個体」で選ぶ。範囲内にいなければ空振り）。素手・他道具はモブの直接タップで攻撃する。サーバーが配置を再計算して実在を検証し、距離は占有範囲まで2マス以内。ダメージは闘技場と同じ式（素手8 + 所持する最良の剣 tier×4、arena.ts の playerAttack を共用）。ドロップは撃破時にサーバー抽選でプロフィールへ直接入る。動き（うろつき・敵対の接近・被弾後の逃走）と描画（素材スプライト・被弾フラッシュ・ノックバック・HP バー・出現ポップ）はクライアントの見た目だけの責務で、位置の真値は持たない。プレイヤー HP は実働（下記「プレイヤー状態」参照。モブは接触でダメージを与える）。 占有当たり判定と接触（2026-11-15 追加）: プレイヤーはモブの占有タイル（現在位置の footprint）へ入れない。当たり判定はクライアント側で、設置ブロックと同じ BlockedTiles 合成にモブ占有を重ねる（combat.ts の mobBlockedTiles / mobFootprintTiles）。占有の真上に立っている間はそのモブの占有だけ通す（閉じ込め防止）。接触は占有範囲までチェビシェフ距離1以内で検出し、敵対モブは接触開始時（継続中は1秒間隔）だけ軽いノックバック（combat.ts の knockbackTarget）＋ hit バーストを発火する。ダメージは /api/worldbox/vitals がサーバー検証して適用する（下記「プレイヤー状態」参照）。
- タイル上書きの読み込みと埋没救済（2026-11-16、読み込み遅延と「読み込み後に壁に埋まる」実害を受けて）: タイルの全件読み（loadTileOverrides）は全件 kvList を毎回走らせず、短TTLキャッシュ（3秒、書き込みはキャッシュへ即時反映）つきにする。クライアントは取得中心から48タイル以上離れたら先読みで取り直し、ワープ/スポーン（placePlayer）と初期位置の確定時にも即時取得する（マウント直後の取得は初期位置 (0.5, 0.5) 中心で実位置とずれるため、それだけに頼らない）。読み込み完了で固体が増えてプレイヤーが固体へ深く重なった場合は、描画ループの埋没救済（半径半分で重なり判定→ findFreeNear で脱出）が毎フレーム働く。浅い重なり（壁への密着）では発火させない。

## インスタンス基盤＋洞窟（2026-11-16 バッチ2）

- 洞窟モブは cave_bat / golem（配置は生成が正、個体状態は worldbox_mobs に空間ID前置キーで保存）。攻撃・接触ダメージとも地表と同じサーバー検証経路を空間対応させた。

## プレイヤー状態（HP・空腹・毒・死亡、2026-11-16 バッチ1）

- 状態の正は profile（bot_kv `worldbox_profiles`）の hp / hunger / status / vitalAt / respawn / restPoint / lastDamageAt / deaths。遷移規則は `web/lib/worldbox/vitals.ts`、入口は `/api/worldbox/vitals`（sync=時間精算 / damage=モブ接触 / set_bed=ベッド設定）。REST ハートビートには触らない。
- HP は 0〜100。空腹は満腹から約20分で 0 になり、0 が続くと HP が減る。バイタル精算はサーバー時刻で行い、1回の精算で進める時間は30分が上限（長期離脱の即死防止）。
- モブの接触ダメージはサーバー側が配置の再計算（実在）と距離（mobs ルートと同じ方式）を検証してから MobDef.attack を適用する。接触の発火間隔は1秒（クライアントの接触発火と一致、サーバー側でも lastDamageAt で担保）。クモ・クモの女王・ミツバチは毒を与えることがある。毒は3秒ごとに HP-2、30秒で切れ、解毒薬・薬草ポーション・はちみつティーで治る。
- 食事は空腹回復に加えて一部が HP も回復する（ItemDef.heal）。薬は新規アイテム「解毒薬」「包帯」＋薬草ポーション（heal / curePoison は ItemDef のデータ）。
- 死亡時: 道具（category tool）は落とさない。それ以外の所持品は各アイテムの半分（切り捨て）を落とす（落とした分は消える。ドロップ実体の回収は将来）。HP は全回復、空腹は 50、毒は消える。
- リスポーン先の優先順（企画書 §9-2 の推奨初期値を採用）: ベッド（踏んだベッドが点になる）→ 最後の休憩地点（ロビー休憩ポッドで休むと戻り先のワールド座標を記録し、HP 全回復＋毒消去）→ 所属国のマーク（首都タイル）→ 原点スポーン。
- 表示: HP と空腹はステージ左上の常時バー（数値つき）＋経済パネル。毒は緑の「毒」ラベル。説明文は置かない。

- ロビー中央広場の北縁（掲示板の西隣）に **ギルドボード** オブジェクトを新設（station `guild`、スプライト `guild_board`）。依頼と役職関連の home はここに一本化し、≡ メニューの旧「国」パネルからは建国・参加・離脱を撤去した（≡ 側に残っていた「建築」パネルも、プレハブ建物の廃止に伴い 2026-11-16 に撤去済み）。
- **依頼**: ユニオン内のアイテム依頼。投稿時に報酬コインを spend オプ（`guild_request_escrow`）で預かり、納品でアイテムが投稿者へ・報酬は earn オプ（`guild_request_reward`）、取消で earn オプ（`guild_request_refund`）で返金。状態は bot_kv 名前空間 `worldbox_requests`、規則は `web/lib/worldbox/requests.ts`、入口は `/api/worldbox/requests`。上限はユニオン20件・1人5件、納品は全量のみ。
- **役職**: 建国・参加・離脱・自分の役職表示はギルドボードの「役職」タブ（データと規則は従来どおり nations 側）。

## 冒険役職と技（2026-11-16 バッチ4）

- 冒険役職は国の役職とは別軸で、本人がギルドボード「冒険役職」タブで選ぶ職業（自由人＋剣士/守護/斥候/採掘者/薬師）。変更はギルドボード前でのみ（station "guild" 検証）、インスタンス内は不可。規則は `web/lib/worldbox/roles.ts`、入口は `/api/worldbox/roles`。profile に role / mastery（役職ごとの `{xp}`、切替えても保持）/ skillAt / tauntUntil / reviveMark / pendingTeleport を保存する。
- 熟練ランクは XP 閾値 [0, 30, 80, 160, 300] で 1〜5。XP の出所は専門行為（剣士=撃破+3、守護=味方を守った被弾+2、斥候=遺跡の宝箱+4/罠+3、採掘者=鉱脈+1（希少以上+4）、薬師=回復アイテム使用+2/蘇生+10）。
- 常時効果は役職ごとに1つだけ（重ね掛けなし）: 剣士=剣攻撃×1.25、守護=最大HP+20 と半径3タイル内の味方の被ダメージ×0.7、斥候=ダッシュ/水泳のスタミナ消費×0.8、採掘者=鉱脈の追加ドロップ抽選30%、薬師=回復アイテムの効果×1.5。
- **技はダブルクリック/ダブルタップの単一ジェスチャで発動する（ユーザー決定 2026-11-16）。スキルボタンは作らない。** 320ms 以内・1タイル以内の2度目のタップを技が消費し、通常行為は二重発動しない。クールタイム中・役職なしの場合は通常タップとして処理する（採掘リズムを壊さない）。対象決定は剣の範囲方式（タップを含む個体→近い個体）に倣い、サーバーが役職・ランク・クールタイム・距離をすべて再検証する（profile.skillAt が正）。
- 技と演出プリセット9種の割り当て（全種を使う）: 剣士=薙ぎ払い（sweep, r1）→旋風斬り（whirlwind, r3）/ 守護=アイスランス（ice_lance, r1、3秒凍結）→サンダーストライク（thunder_strike, r5）、加えて自分のタイルへのダブルタップで挑発（taunt、5秒）/ 斥候=ポイズンフィールド（poison_field, r1）→アローレイン（arrow_rain, r3）/ 採掘者=ファイアーボール（fireball, r1）→メテオ（meteor, r5）/ 薬師=ヒーリングゾーン（heal_zone、全ランク）。技は「ランクで上位に置き換わる」方式で、発動できるのは常に最上位の解禁技1つ（挑発のみ例外）。演出は fx.ts の SkillFxKind プリセット（予告→本体の2段構成、粒は spawnSkillFx）。
- ポイズンフィールドは設置時に3ティック分を即時解決する簡略化（継続ゾーンの定期処理は持たない）。
- 蘇生は薬師の専門行為: 死亡地点（bot_kv `worldbox_deaths`、90秒保持）の2.5タイル以内で死亡マーカーをダブルタップすると、対象はその場で HP 30% まで回復して戻る（pendingTeleport を vitals sync が配送）。1遠征（同一空間・30分）につき1回まで（reviveMark）。
- クールタイムの表示は説明文ではなく構造で: HP バー脇の役職チップに conic-gradient の減衰扇＋熟練ドット。
- 凍結中のモブは接触ダメージを与えず、氷色で描く。斥候は遺跡の罠を3タイル以内で赤く視認でき、採掘者は洞窟の鉱脈が脈打つ枠で見える。
- ダンジョンの解禁ゲート（バッチ5で使用）: フロア2はパーティ内にランク2+が1人、ボス部屋はランク3+が1人必要（partyGateSatisfied）。
- BGM に洞窟（cave）/ダンジョン（dungeon）場面を追加（bgmSceneFor が空間IDで判定）。従来どおり Web Audio 合成のみ・音声ファイル禁止・BGM バスに lowpass をかけない。

## パーティとダンジョン（2026-11-16 バッチ5）

- パーティはダンジョン入口の前でだけ編成する場面単位の集まり（ロビー永続化なし）。リーダー+最大3人、ユニオン跨ぎ可、ソロ可。招待はリーダーが近くのプレイヤーをタップ（プレゼンス検証7タイル、60秒で失効）。解散はリーダー退出/全員退出/ダンジョン終了。状態は bot_kv `worldbox_party`（本体+メンバー/招待の索引キー）。入口は `/api/worldbox/party`、規則は `web/lib/worldbox/party.ts`。
- ダンジョンの空間 ID は既存形式 `dungeon:<入口x>,<入口y>:<層>`（層は0始まり）を踏襲し、パーティ分離はセッションキー `#<partyKey>` とプレゼンスの party フィールドで担保する（SPEC の `dungeon:<パーティID>` 形式からは意図的に逸脱。分離と破棄の意味論は保持）。セッションは bot_kv `worldbox_instances` の `<1層目空間ID>#<partyKey>`、ルートは全て個人別（宝箱の取得記録も個人キー）。
- 生成は決定的（52×52、4層=3フロア+ボス層、3×3部屋+通路、BFS最遠=ボス部屋）。各フロアに番人（ghost）がいて倒すと `dungeon_key` を落とし、境界通路の鍵扉を開ける。フロアボスを倒すと階段が開く（サーバー側でも前層ボス撃破を攻撃ゲートとして検証）。ボスは入口ごとに決定的: 中層は ogre/spider_queen 交代、最下層は ogre/spider_queen/dungeon_dragon の3種から決定的選択。
- モブ HP はパーティ人数で ×1.0/1.6/2.2/2.8（攻撃力は不変）。ダンジョン内の技はフロアボスを対象にしない（進行登録は通常攻撃の経路に一本化）。
- 熟練ゲートをサーバーでも検証する: フロア2以降の攻撃・宝箱・扉はパーティ内にランク2+が1人、ボス層はランク3+が1人必要（partyGateSatisfied、members の profile から判定）。
- 全滅（全員 dead/departed）でインスタンスは閉鎖し、途中離脱は進行破棄。ダンジョン内死亡のリスポーンは入口前。ボス宝箱はボス撃破必須で罠無効（通常宝箱の罠は HP-10 のみ）。
- クリア報酬 `dungeon_clear` = 500（暫定）は週1回・その場の生存メンバー全員へ。earn ホワイトリストに TS/Python 両側で追加済み。ボス素材は最上位の鍛冶レシピに接続（dragon_scale→ミスリル剣、ghost_tear→ゴーストランタン）。

## ソーシャル（2026-11-16 バッチ6）

- ネームプレートは「ユニオン色の枠プレート」に統一する: 中身は Discord マーク（描画）+ 冒険役職シンボル + 名前 + 熟練ドット（ランク2以上）。プレゼンス GET が role/rank/party を落としていた問題も合わせて修正（WS 中継と同じフィールドを REST でも返す）。
- プレゼンスの間引き: ワールド空間では自分の 48 タイル以内だけを返す（thinPresenceNear、近い順・上限32）。ロビー/テント/インスタンス等の小空間は全員返す。間引きは「新しい順の上限」より前に適用する。
- 他プレイヤーのタップはプロフィールチップ（役職シンボル/名前/熟練ドット/役職名）を出す。パーティ招待はチップのボタンから（旧: リーダーのタップ即招待は廃止し導線を一本化）。
- チャットは3チャンネル（`web/lib/worldbox/chat.ts` + chat-online.ts + `/api/worldbox/chat`）: 近距離（12タイル・60秒で揮発）/ 全体（同一空間内・5分で揮発）/ ユニオン（ギルドボード掲示として24時間保持、bot_kv `worldbox_union_board`）。連投は1.5秒間隔で制限。本文上限は掲示板と同じ120文字。
- ユニオンの Discord 連携: ギルドボード「掲示」タブで王/大臣がチャンネル ID を設定（bot_kv `worldbox_union_settings`）。ユニオン投稿は送信箱 `worldbox_chat_outbox` に積まれ、Bot 側ワーカー（core/general/circulation/worldbox_chat.py、15秒ポーリング）が連携チャンネルへ投稿して削除する。メンションは常に無効化。失敗したエントリは保持上限24時間で掃除される。

## ユニオン戦争と日次ローテーション（バッチ7a、2026-11-16）

- 戦争状態は bot_kv `worldbox_war`（キー "state"）に一括保持し、検証と遷移は
  `web/lib/worldbox/war.ts` が担う。戦争は48時間、終了後の再宣言クールダウン24時間。
- レイド宣言は国王のみ（POST /api/worldbox/war action=declare）。修復中
  （マーク破壊から24時間）のユニオンへは宣言できない。
- ユニオンマーク = 首都タイル。マーク HP 100、1時間ごとに +10 自然回復、
  攻撃1回 -10（プレイヤー単位5秒間隔、首都から3.5タイル以内のプレゼンス検証）。
  HP 0 でレイド成立: その戦争は終了し、破壊側・被破壊側とも記録（raids、最大50件）。
- 戦争中だけ他ユニオンの設置ブロックを削れる: 採掘に耐久（アイテムの durability）が
  付き、ダメージはツルハシ tier で 20+tier×15。壊し切るとブロックは破壊者が回収する。
  平時は従来どおり所有者のみ。収納コンテナの中身は従来どおり保護される。
- 繁栄ランキングはギルドボード「役職」タブに表示（順位・国名・繁栄度・人数、
  ユーザー名はテキストのみでメンションにしない）。
- ショップの日次ローテーション: 価格は日キー（UTC日付）で決定的に ±10%（5%刻み）、
  品目が8を超えるジャンルは毎日75%の窓が回る（`shops.ts` の daily* 関数）。
  サーバー検証（checkDailyStock）と表示は同じ関数を使う。Plan A の価格帯は不変。
